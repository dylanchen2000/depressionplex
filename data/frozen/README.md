## DP-059：DP-053 全量跑的结果快照（2026-09-07 冻）

### 为什么有这两个文件

DP-053 跑完全量之后，27 个试次的软件数字**只存在于 `/tmp/dp053_runs/`**。
`/tmp` 是易失目录，机器一重启就没了；而 DP-055 里所有偏差数字（r=0.7641、
平均绝对偏差 35.15 s、达标 5/26）都是从这批数据算出来的——**它们的原始出处
随时会消失**。所以先冻住。

生成方式：`python3 scripts/dp059_freeze_run_snapshot.py /tmp/dp053_runs data/frozen`

| 文件 | 是什么 |
|---|---|
| `DP-059_软件全量快照_DP-053.csv` | 27 份单试次 CSV **原样**合并，列名不动，多带 `trial_id_raw` 与 `_source_csv` 两列出处 |
| `DP-059_软件人工对比_2026-09-07.csv` | 软件 ↔ 人工逐试次对比，**口径计算全部做在这里**（见下） |

### 这不是真值，是快照

**读之前必须知道的三件事：**

1. **软件那一列会随代码变。** 它是 `main` 在 DP-053 落地时那一版跑出来的，
   不是"软件的正确答案"。代码一改，这张表就旧了——**重跑之后要另开一个日期的文件，
   不许原地覆盖**，否则将来没法回答"当时那个数是怎么来的"。
2. **人工那一列也不是金标准。** 它是两位评分员 **T2 档**的平均，
   两人极差中位 19.33 s、最大 66.79 s（DP-055）。T1 精标（SOP v1.4 第六节）
   才是定门锚点，T-1 那 8 段回来之后要单独出一份。
3. **`bias_s` 是"软件 − 人工平均"，不是误差。** 谁错还没归因（DP-055 开着）。

### 口径写清楚，因为 UI 支线只许画不许算

| 列 | 怎么来的 |
|---|---|
| `human_immobility_mean_s` | `data/human_scores/recomputed/human_scores_recomputed_DP-012.csv` 中该试次 **`status == accepted`** 行的 `immobility_s` 算术平均 |
| `human_range_s` | 同一批的 max − min（**评分员之间的分歧**，不是置信区间） |
| `bias_s` | `software_immobility_s − human_immobility_mean_s` |
| `g8_pass` | `abs(bias_s) <= 17.7`（G8 门槛，DP-047 定） |
| `unknown_fraction_window` | `unknown_frames_window / window_frames` |

**空值一律是"没有"，不是 0**（DP-032）：

- 软件没产出数字 ⇒ `bias_s` / `abs_bias_s` / `g8_pass` **留空**，`note` 写明；
- 没有人工评分 ⇒ 人工那几列**留空**，`note` 写"无人工评分 ⇒ 无法比对（不是 0，是没有）"。
  27 个试次里有 **1 个**属于这种（`30mg_2周-ch4`，唯一一只从没被任何人评过的鼠，
  见 `docs/TST_人工任务清单_2026-09-06.md` 的 T-2）。

**任何下游（含 UI）把这些空值渲染成 0、或拿它参与平均，都是缺陷。**

不许写出一份和已发布数字打架的表：

| 平均偏差 | +1.74 s | +1.74 s |
| 平均绝对偏差 | 35.15 s | 35.15 s |
