---

## 0. 一句话

人工用秒表评出每个试次的"在动总时长"，本 spec 定义**如何与软件输出比对、如何判定验收通过**。

这是 TST v1 出货的**门**：`trial 级 immobility 总时长 vs 人工，Pearson r ≥ 0.95`。

---

## 1. 为什么是秒表法而不是逐帧标注

| | 能测什么 | 能否定位错因 | 成本 |
|---|---|---|---|
| **秒表法（本次）** | 整套流程的**总体**准确性 | 不能 | 约 9 min/试次 |
| 逐帧原语 | 每个原语单独的准确性 | 能，是诊断工具 | 30–60 min/试次 |

**关键认识**：金标准（Can et al. 2012）给评分员的规矩里明确规定「仅前肢的小动作」与
「因惯性产生的钟摆式摆动」**不算 mobility**。所以评分员在按秒表时**本来就在做这两个判断**——
只是没有分开记录。

因此 **r ≥ 0.95 这一个指标已经在给 Passive Swing 与 Forelimb-only 的处理施加压力**：
若软件错把钟摆当成在动，软件的 immobility 会系统性偏短，r 立刻掉。

**逐帧原语标注因此降级为"r 不达标时的诊断手段"**，不是前置任务。这是有意的顺序，不要提前做。

## 2. 输入契约

### 2.1 人工评分文件（CSV，每位评分员一份）

| 列 | 类型 | 说明 |
|---|---|---|
| `scorer_id` | str | 评分员标识 |
| `trial_id` | str | 与软件侧一致的试次标识（建议 `<video>-ch<N>`） |
| `mobile_seconds` | float | **在动**总时长，秒。注意：人工记的是 mobile，软件输出的是 immobility |
| `tail_climbing` | bool | 是否出现过爬尾巴 |
| `unscoreable` | bool | 是否无法评分（脱落/遮挡等） |
| `note` | str | 可空 |
| `scored_at` | date | |
| `presentation_order` | int | 该评分员看到本试次的序号（用于查顺序效应） |

**校验（必须实现，缺一即拒绝入库）**：
- `mobile_seconds` ∈ [0, 试次时长]；越界报错，不裁剪
- `unscoreable=True` 时 `mobile_seconds` 必须为空
- 同一 `(scorer_id, trial_id)` 不得重复
- 必须恰好两位 `scorer_id`，且两人覆盖的 `trial_id` 集合完全相同

### 2.2 软件侧

读 result package（契约复用 DrugEffectPlex：`result.json` = 模型输出 / `review.json` = 人工复核，
`event_id` 对齐，`review.json` 永不写模型分数）。

需要取出：`immobility_seconds`、`scoreable_frames / total_frames`、`unknown_fraction`、
`TrialValidity`、`tail_climbing` 事件是否出现、以及所用参数快照与模型/代码版本指纹。

## 3. 三个必须防的坑

### 3.1 单位与方向：人工记 mobile，软件出 immobility

`immobility_human = trial_duration − mobile_seconds`

**符号错误在这里极易发生且极难发现**（r 仍然很高，只是符号反了或有常数偏移）。
要求：写一个断言测试，构造 `mobile=0` 与 `mobile=trial_duration` 两个极端，
检查换算后分别等于 `trial_duration` 与 `0`。

### 3.2 计分窗口：TST 是全程，不要照抄 FST

- **TST：全程 6 min 全部计分**
- FST：6 min 里只计**后 4 min**（前 2 min 适应不计）

比对前**必须核对软件用的窗口与人工评分的窗口一致**，不一致直接报错退出，不要静默按比例缩放。

### 3.3 时间单位

按项目**单位不变量**：全部用**秒**，内部按 fps 换算。不得出现帧数常数。

---

## 4. 参考值与排除规则

### 4.1 用哪个人工数字当真值

**两位评分员的均值。** 同时**单独报告**两人之间的一致性（见 §5.3）。

理由：两人均值比任一人更接近真值；但若两人本身不一致，均值的意义要打折——所以两个数字必须一起看，
不能只报 r。

### 4.2 排除规则（按金标准）

| 情况 | 处理 |
|---|---|
| 任一评分员标 `unscoreable=True` | 该试次**排除**出主指标 |
| 两位评分员**都**标 `tail_climbing=True` | 该试次**排除**出主指标（金标准要求排除爬尾动物） |
| 只有一位标 `tail_climbing=True` | **不排除**，但列入"需复核"清单 |
| 软件 `TrialValidity` 为 `exclude`(脱落) | 排除 |
| 软件 `TrialValidity` 为 `needs_repair`(截断) | **不排除**，且必须在报告中显著标出——这是软件 bug，不是数据问题 |

**必须同时报告排除前与排除后两组数字。** 只报排除后的会掩盖排除率异常
（例如软件把大量正常试次判成脱落）。

## 5. 输出报告（全部为必需项）

### 5.1 逐试次对照表

`trial_id | 人工A | 人工B | 人工均值 | 软件 | 差值 | 可评分帧占比 | unknown占比 | validity | 标记`

### 5.2 主指标

- **Pearson r + 95% 置信区间**（Fisher z 变换求 CI）
- **Bland-Altman**：偏差（bias）、一致性界限（±1.96 SD）、以及**偏差是否随均值变化**
  （做一次差值对均值的线性回归，斜率显著非零即为比例性偏差，要报出来）
- 参与计算的 n、被排除的 n 及各排除原因计数

> **为什么 r 不够、必须配 Bland-Altman**：r 只看"排序是否一致"。软件若把每个试次的
> immobility 都系统性多算 20 秒，r 仍可能 0.99，但每个数都是错的。
> **Bland-Altman 才看得出系统性偏移。**

### 5.3 评分员间一致性

- 两人的 ICC(2,1) 与 Pearson r
- 两人差值的均值与 SD
- **若两人一致性低于软件与均值的一致性，说明真值本身不稳** —— 此时主指标不可采信，报告必须置顶警告

### 5.4 尾巴攀爬 / 脱落的混淆矩阵

分别对 `tail_climbing` 与 `unscoreable/detached` 出 2×2 表（人工 vs 软件），给敏感性与特异性。

**尾巴攀爬要求召回优先**（宁可误报不可漏报）——漏报会把该排除的动物留在数据里。

### 5.5 分母（不可省）

- 各试次可评分帧 / 总帧、`unknown` 占比的分布
- **无分母的指标不可审计。** 一个 immobility 数字必须能回答"这是在多少有效数据上算出来的"

### 5.6 顺序效应检查

用 `presentation_order` 检查每位评分员的 `mobile_seconds` 残差是否随顺序漂移
（疲劳/学习效应）。有显著趋势要报出来。

---

## 6. 验收判据

| # | 判据 | 门槛 |
|---|---|---|
| **V1** | 软件 immobility vs 人工均值，**Pearson r** | **≥ 0.95** |
| **V2** | Bland-Altman 偏差 | 绝对偏差 < 试次时长的 5%（6 min 即 < 18 s），且无显著比例性偏差 |
| **V3** | 评分员间 ICC | ≥ 0.90（低于此则真值不稳，V1 不予采信） |
| **V4** | 尾巴攀爬召回 | ≥ 0.95 |
| **V5** | 脱落/无法评分识别 | 敏感性 ≥ 0.90，且**假阳性为 0**（不得把正常试次判成脱落） |
| **V6** | `needs_repair`（截断）试次数 | **必须为 0**。非零即为软件 bug，须修复后重跑，不得以"排除"绕过 |
| **V7** | 有效样本量 | 排除后 n ≥ 25 |

## 7. 铁律

| 铁律 | 原因 |
|---|---|
| **禁止用本脚本的输出去调任何参数** | θ_mob 与全部 bout 参数标 FROZEN provisional。拿验收集调参 = 拿考卷答案改考卷，r 就没有意义了。要调必须另取独立数据 |
| 每次运行必须记录参数快照与代码/模型版本指纹 | GLP 可追溯；也防"改了参数忘了重跑" |
| 报告须同时给排除前/排除后两组数字 | 防止排除率异常被掩盖 |
| 人工文件带有任何软件预填痕迹即拒绝 | 锚定偏差会虚高一致性，污染真值（工具级已有同类约束，此处沿用） |
| 判据不达标就报不达标 | 不要放宽门槛。门槛数字都有依据（同类商业软件 r=0.58–0.78，我们的卖点就是 0.95） |

## 8. 建议顺带做的一件小事：最小计时工具

SOP 里要求评分员「在动就按住键、松开即停」，且**不得看到累计读数**（看着累计时间会产生偏差，
金标准原文也建议遮住秒表）。

通用秒表软件做不到"遮住读数"，而且人工转抄数字会引入错误。建议实现一个极简计时器：

- 按住某键计时、松开停止；界面**只显示进度条，不显示累计秒数**
- 视频播完自动落盘成 §2.1 的 CSV 格式，含 `presentation_order`
- 每位评分员的试次顺序由工具随机生成并记录
- **不提供任何"查看软件结果"入口**

这不是必需项，但它同时解决了转抄错误、读数偏差、顺序随机化三件事，成本很低。
