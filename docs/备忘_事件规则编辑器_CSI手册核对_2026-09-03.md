# 备忘：EthoPlex 事件规则编辑器 vs 我说的组合语义 vs CSI 手册

> 2026-09-03｜Capy｜回答道俊三个问题：是不是同一回事？manual 里有没有？
> 核对范围：我手上有的三份手册 `Manual_ForcedSwimScan`（80 页）、`Manual_TailSuspScan`（57 页）、
> `Manual_HomeCageScanHRT`（89 页），逐份 grep 过 rule / editor / threshold / AND / OR。
> **TopScan 的手册我没有**，只看过你给的三张截图——凡涉及 TopScan 的说法都只以截图为据。

---

## 0. 三句话

1. **是同一回事，但 TopScan 那个比我说的多一样东西**：它把**开始规则和停止规则分开**，
   这是双阈值滞回状态机，我提的 AND/OR/N-of-M 只是**对称**的单阈值组合，少了这一层。
2. **CSI DepressionScan 两份手册里没有事件规则编辑器。** FST 手册里有一个同名功能
   `Start/Stop Setting`，但它是**分析时间窗控制**（第几帧开始、跑多少秒停），跟行为条件无关。
3. **但 AND/OR 的语义在 FST 手册里确实存在**——以一个**写死的三选一单选框**的形式。
   所以准确的说法不是「CSI 没有」，而是**「CSI 把组合语义硬编码成了几个预设选项，没有开放成编辑器」**。

### 1.1 FST 手册里那个「写死的 AND/OR」（Motion Setting Tab，§6.1.2）

原文（Float/Immobility Mode Settings）：

- **Full Body** —— "the strictest condition"，整个身体都要满足运动判据 ⇒ **上半 AND 下半**
- **Either Half** —— "the most lenient condition"，上下任一半满足即可 ⇒ **上半 OR 下半**
- **Bottom Half Only** —— 只看下半，完全忽略上半 ⇒ **单操作数**

Escape/Struggle 侧同构（Full Body / Top Half Only）。

**这就是 AND / OR / 单项三种组合，但**：

- 操作数**恒为两个且写死**（上半身、下半身，由一条固定几何线切出来）
- 组合方式是**三个单选按钮**，不是表达式
- 不能加操作数、不能嵌套、不能改成「上半 AND (下半 OR 尾部)」
- 没有 N-of-M

⇒ **概念在，可编辑性不在。** 这个区别不是学术性的：客户拿到 CSI 只能在
「严格 / 宽松 / 只看下半」三档里挑一档；拿到编辑器可以按自己的实验写条件。

### 1.2 FST 手册里那个 `Start/Stop Setting`（§6.1.3.2）——**同名不同物，别搞混**

原文：设置**分析何时开始、跑多久停**，单位可选帧或秒，可按缸单独设，**每缸只能有一条规则**，
存在 `.SET` 文件里。

**这是时间窗控制，不是事件定义。** 没有条件、没有阈值、没有 AND/OR。
如果有人拿 FST 手册这一节当「CSI 也有事件规则编辑器」的依据，那是读串了。

### 1.3 HomeCageScan 有的是**等价类与合并**，不是条件组合

- **Behavior Match**：选一个主行为，勾一批行为算作等价。三条总规则
  **Self**（自身必属本类）、**Symmetry**（对称互认）、**Propagate**（A≡B 且 B≡C ⇒ A≡C）
- **Merge tab**：把时间上相继的行为合成一个，默认预置 4 条（Rear Up / Come Down / Hang Vertical / Hang Cuddled）

两者都作用在**已经固定的 40 个行为词表之上**，是**事后重标签与聚合**，
不是「用原语和阈值拼出一个新行为」。**表达能力上严格弱于编辑器。**

值得抄的是那三条总规则：**Symmetry 和 Propagate 是给等价关系加闭包**，
我们的规则表（原语 → 类别映射）如果允许用户改，也会遇到同一个问题
（改了 A≡B 要不要自动推 A≡C）。**这三个开关是现成答案，直接借。**

### 1.4 TailSuspScan：什么都没有

TST 手册里既没有规则编辑器，也没有 AND/OR 描述，**连 bout 参数的默认值都不给**
（原话把 Mobility Thresh 称作 "just a relative measure"）。
这与我们已知的 CSI 最大软肋是同一件事。

> 提醒（事实口径）：我们现用的 `CSI_FST_DEFAULTS`（First Combine 5 / Noise 5 帧 /
> Combination 30 帧 / Length 30 帧 / Section 5 s）**全部只有一个来源**——
> TailSuspScan 手册里一张标题为 "Forced Swim Settings" 的图（Figure 4.1）。
> **没有第二处可交叉验证。** 这批数字仍标 FROZEN provisional，别当既成事实引用。

## 2. TopScan 那个编辑器比我提的多什么

从截图能确认的结构：三个 tab **事件 / 开始规则 / 停止规则**；后两个 tab 各有
**与规则**框 + **或规则**框、一个「与/或规则」单选、一个「最终逻辑」单选；
左侧**可用规则列表**树（General Temporal、Miscellaneous、Light Event、Area、Motion、
Sniffing、Circling、HeadTwitching、Scratching、Stereotypic Events、Rearing）；
「应用至所有观察区」「添加已选规则」；事件 tab 上有**范式**（Non-Social/Single Animal）、
`AnimalNum[1]`、以及一个**时长约束**按钮。

**我提的 AND/OR/N-of-M 覆盖了「与规则框 + 或规则框 + 最终逻辑」和「时长约束」。**
**没覆盖的是开始规则与停止规则分开这一件事，而这一件事是结构性的。**

### 为什么它是结构性的

开始条件与停止条件不同，等于**双阈值滞回**：进入事件用严条件，退出用松条件。
状态机比单阈值多一个记忆位。

我们现在的 `bouts.py` 是**对称**的：单一 θ_mob 出逐帧二值标签，
再走 First Combine → Noise → Combination → Length → Section 五段后处理。
**合并/过滤能修掉短抖动，但修不掉「阈值边界上长时间反复穿越」**——
一只动物运动量正好卡在 θ_mob 附近时，逐帧标签会持续翻转，
后处理只能选一边（合并成一大段在动，或删成一大段不动），两种都是猜。
滞回从根上避免这个：一旦进入某状态，要跨过另一个阈值才出来。

**这不只是工程细节，它对着一个我们已经量到的真实现象。** §4 那条评分员颗粒度
规律（在动段中位 1.08–3.36 s 决定总时长差 28.6 s）说的正是**边界处的停顿算不算断开**。
人的分歧点和软件的抖动点是同一个位置。**滞回的两个阈值，正是把这个选择显式参数化。**

### 但有代价，必须先说

**自由参数从 1 个变 2 个。** SPEC v2 §5 的 LOVO-CV 之所以便宜，全靠
「决策层只需拟合 θ_mob 一个标量，27 个试次充裕」。变两个之后：

- 27 个试次拟合 2 个参数仍然可行，但 **G2（θ_mob 跨 7 折变异系数 ≤ 15%）会变弱**，
  因为两个参数可以互相补偿，各折拟合值会更散
- 而 G2 是我们**唯一能零成本反驳 CSI「阈值需逐视频试错」的证据**，不该拿它换功能

**建议（DP-018）**：

1. v1 **保持单阈值**，θ_mob 一个标量，G2 照原样跑，先把那个证据拿到手
2. 同时把滞回**写进接口但冻结关掉**：`θ_exit = k · θ_mob`，**k FROZEN = 1.0**，
   带标度不变性测试（k 无量纲，天然满足单位不变量）
3. `spike/hysteresis-bouts` 分支上量一件事：**k=1 时，逐帧标签在 θ_mob ±20% 带内
   反复穿越的帧占多大比例**。这个数决定滞回值不值得开——占比小就不必开，
   占比大再开，并接受 G2 变弱、在报告里如实说明

**顺序很重要：先拿 G2，再考虑加参数。** 反过来做会把最有价值的证据换掉。

## 3. 对 EthoPlex 那边的两条建议

**一，规则表达式的 schema 三条产品线共用一份**（DP-019）。
EthoPlex 现在做的编辑器、DepressionPlex 的规则引擎、DrugEffect 的决策层，
如果各写一套 JSON，将来「CSI 兼容模式」这类导出口径就得写三遍。
建议：EthoPlex 定稿前把 schema 拿出来对一次，我按 DepressionPlex 的原语表验一遍能不能表达。
需要覆盖：AND / OR / N-of-M、时长约束、**开始/停止分离（即使先冻结）**、以及
HomeCageScan 那三条等价闭包开关（Self / Symmetry / Propagate）。

**二，编辑器开放给客户，就必须同时开放「阈值以物理单位表达」这条约束。**
我们的单位不变量（空间用 BL、时间用秒，禁止像素/帧常数）在内部是硬规矩。
一旦客户能自己写规则，如果编辑器允许他填像素或帧，
**我们对 CSI 最大的差异化（跨实验室可比）当场作废**——客户自己写出来的规则不可移植，
出了问题算在我们头上。

**编辑器的数值输入框应当只接受 BL 与秒，不接受 px 与 frame。**
这条要在 UI 层强制，不能只写文档。这是我对那个编辑器唯一的硬要求。
