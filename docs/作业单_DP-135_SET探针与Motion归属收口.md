## 一、要收口的是哪一句

`depressionplex/csi/fst_import.py` 里：

```python
MOTION_PAIR_UNRESOLVED_IDX = ((5, 6), (7, 10), (8, 11), (9, 12))
```

这 4 对同类型 Motion 字段（Min Length / Noise / Merge / Bin）的**「挣扎侧 vs 放弃侧」归属
是约定推断，不是字节级证明**。同一处注释写清了收口条件：

> 收口只需一份把**任一个**参数的挣扎侧与放弃侧填成**不同值**的 `.SET`

读的时候猜错只是标签难看；**写的时候猜错，CSI 会把两侧阈值对调着用**，算出来的秒数
照样是一串正常数字。所以这一条不收口，B 线任何"我们按 CSI 的口径复现了"都不成立。

## 三、两条路，选一条（这就是要拍的板）

先把两种"不许"分开，它们不是一件事：

| | 是什么 | 依据 | 现状 |
|---|---|---|---|
| **我们的代码加载/执行 CSI 的 DT** | 让产品或参考实现去调 CSI 自己的动态库 | Spec B:32 | **架构永久禁止**，与授权无关，任何 scope 扩展都改不了这一条 |
| **黑盒运行原 EXE 做动态观测** | 人在合法装机的 Windows 上开程序、读参数面板 | Spec B:36 / B:38、R1 §9:312-320 | **不是永久禁止**，但需要一条覆盖该动作的明确 scope；**在本次核对的材料中未查到覆盖本动作的许可**（R1 §9 只写到"建议将来在隔离兼容 Windows VM 里做动态验证"，那是建议不是许可） |

| 方案 | 谁做 | 需要什么 | 产出 |
|---|---|---|---|
| **A** | 道俊（或客户）在他那台**合法装机**的 DepressionSuite 机器上 | 第四节 6 步，约 5 分钟；机器与操作人本就是许可范围内的使用者 | 面板截图 + CSI 另存回来的 `.SET` + 程序版本号 |
| **B** | 我们，在**隔离 Windows VM** 里 | 逆向授权范围**显式扩展**到"运行原 EXE 只为读参数面板"（R1:320 的要求），VM 不落任何客户数据；由用户明确选定并批准 | 同上 |

**A 便宜得多，也不需要新开动态授权**；B 只有在 A 走不通时才提，而且要用户明确批准。
在没有一条覆盖该动作的许可之前，agent **不执行**原 EXE、**不加载** DT。

## 五、交回来之后我们做什么（判读表）

判读按**面板分组的真实标题**，不按左右/上下位置：

| 观察到 | 结论 | 改动 |
|---|---|---|
| `Struggle/Escape/Climb Settings` 组显示 **20**、`Float/Immobile Settings` 组显示 **40** | idx5 落在 `Struggle/Escape/Climb Settings` ⇒「低 idx = high/Escape 侧」的约定推断**成立** | `MOTION_FIELD_HINTS` 去掉 idx5/idx6 的「约定推断」字样；`MOTION_PAIR_UNRESOLVED_IDX` 删掉 `(5, 6)` |
| `Struggle/Escape/Climb Settings` 组显示 **40**、`Float/Immobile Settings` 组显示 **20** | 归属**反了**（idx5 是 low/Immobile 侧） | 交换 idx5/idx6 的 high/low 标签，同样删掉 `(5, 6)` |
| 两组显示同一个数 / 都不是 20、40 / 另存件用 `parse_set` 读不动 | CSI 没按我们写的读，或面板另有取整，或另存的不是这份参数 | **一律停下**，不许改标签、不许猜读数；把另存的 `.SET` 与探针逐字节差分，看 CSI 改了哪几个字节 |

**只更新这一对的映射**，另外 3 对（`(7,10)` Noise / `(8,11)` Merge / `(9,12)` Bin）
仍是约定推断 —— 一次探针只收一个 bit，按需在后续轮次逐对收。

**读回证据的落盘方式**：用 `scripts/dp135_record_readback.py` 生成一份**新的**
`*.readback.json`，按 sha256 指回原探针。**生成记录 `*.provenance.json` 永不被改写** ——
它里面那个 `csi_read_back_verified` 恒为 `false`，谁把它就地改成 `true`，
就等于在"我们造了什么"的记录里宣称"CSI 已经读回过"，两件事混成一件，原始记录也毁了。

`csi_read_back_verified = true` 的**唯一**权威在那份新的读回记录里，条件是五件事齐：
① 原 EXE 身份与版本；② 探针 sha256 与生成记录一致；③ 操作人/机器/观测时间；
④ 能看到两个分组真实标题的截图；⑤ CSI 另存回来的 `.SET` 的 sha256 与被探两个下标的读数。
**截图不算读回证据，另存件里出现那两个值也不单独算**：截图证明"人在面板上看到什么"，
另存件证明"哪个下标的字节是哪个数"，**两个对上**才定死归属。
另存件若与探针**逐字节相同**，脚本会拒绝，除非显式加 `--allow-identical-to-probe`，
且记录里会标成 `weak_identical_bytes`（很可能只是被拷回来了）。

- **不改冻结口径**：TST θ_mob / ASSAY_WINDOWS / CSV 字段 / 历史数据 / 验收门与本单无关。
- 探针**不许**用来跑分析出数（第五节说明），也**不许**当成客户参数文件的替代品。

## 七、复现探针（谁都能重造，结果应当逐字节相同）

```bash
/tmp/dpx311/bin/python scripts/dp135_make_set_probe.py \
  --template "~/Work/depression抑郁绝望/9月10日集中标注/CSI分析强迫游泳数据_对照参数/正常1-4对照.SET" \
  --package-dir "~/Work/csi_probe/正常1-4对照_minlen_探针包_20260919" \
  --pair 5,6 \
  --manifest /Users/dylanchen2000/Work/dpfstcsi-wt/docs/共用输入身份清单_v1.csv \
  --expect-template-sha256 fd9596e5a588e15c053585c0d5693de44d29e2f4eaf6b0f4a70cda5a37fafce2
```

- `--pair 5,6` 与 `--pair 6,5` 都收；**下标与值成对移动**，反着写不会把 20 写到 idx6 上。
- `--values` 不给时用脚本**记录的默认值**（本对是 `20,40`，两侧都与模板原值 15/15 不同）。
  这不是"钉死"，是**记录在案的默认值**，可以显式覆盖：`--values 22,35`。
  另外 3 对各有自己的默认值（Noise `12,25` / Merge `22,35` / Bin `6,11`），
  **都是按这一批已观察到的模板值挑的**，换一批材料要重新挑并记录。
- 两侧都等于原值 ⇒ 拒绝（逐字节一致，没有信息量）；**单侧**等于原值 ⇒ 仍然出探针，
  并在来源记录里写明 `sides_already_at_target`（只要两个目标值互不相同，探针就有判别力）。
- `--out` 与 `--package-dir` 二选一：`--package-dir` 是**一个目录一次 `os.replace`**，
  目录本身就是原子的交付单元；`--out` 模式是两次 `os.replace`，
  **不构成跨文件原子事务**，靠"发布前整体校验 + 失败逆序撤回本次发布物 + 半包检测"兜。
