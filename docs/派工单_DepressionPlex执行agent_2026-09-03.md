## 2. A 轨：胶带走廊标定（DP-020，主线）

**分支**：`feat/tape-corridor-calibration`，从 `master` 开
**规格**：`docs/SPEC_胶带走廊标定_v1.md`（已完整，含设计契约、实现路径、7 条坑、可测验收）

### 要解决的具体问题

P2 硬门实测里，**第一批帧（t≈24 s 剧烈挣扎期）4 个隔间有 2 个判别不稳**，
动物与胶带频繁接触时分割失效；第二批静止期（t≥240 s）4/4 正常。

**已定性：这是标定问题，不是阈值问题。** 相机固定，胶带走廊的位置全程不变，
应当作为确认过的几何语义**标定一次并复用**，而不是每帧去推断。
现在的每帧启发式已经被证明会在真实素材上误杀动物（纯胶带上端有时是较宽的结头）。

### 做什么

1. `geometry.py` 新增语义角色：每隔间的 `suspension_bar` 与**胶带列区间**
2. 新增标定函数：按**"暗频率"**标定（哪些列在多帧里持续为暗），**不要按形状标定**
3. 扩展 `segment_animal()` 签名接受 `corridor` 参数；分割时先减去胶带走廊，
   用走廊定位动物顶端后按行截断
4. `corridor=None` 时**必须与现基线逐比特一致**（C3）

### 三个必须过的边界情况（SPEC §4，一个都不能"设计掉"）

| 情况 | 正确行为 |
|---|---|
| 动物完全落在走廊列区间内 | **不得静默返回胶带**。必须能返回动物，或显式报警 |
| 动物爬到走廊上方 | 这是**真实行为**（攀爬），不得当噪声抹掉 |
| 走廊上端有较宽结头 | 不得因"宽度不恒定"误判为动物 |

### 验收（照抄 SPEC §5，全部要跑出数字，不达标就写出来）

| # | 判据 | 现状基线 |
|---|---|---|
| A1 | A 批（挣扎期）4/4 隔间合理：面积 120–400 px、伸展度 ≥1.8、无报警 | 现 2/4 |
| A2 | 没有一个隔间挑中胶带；伸展度 ≤8 | 现坏例 **10.64** |
| A3 | 面积跨帧 SD ≤ 均值的 20% | 现坏例 85±57 ≈ **67%** |
| B1 | B 批（静止期）保持 4/4，面积与基线偏差 ≤±25% | 现 4/4 |
| B2 | 最低 RAD 隔间面积抖动 p90 ≤ 0.02 | 现 **0.0035**（不得变差） |
| C1 | `run_tests.py` 49 测试全绿 | — |
| C2 | 上表三个边界情况各补一条回归测试 | — |
| C3 | `corridor=None` 与基线**逐比特一致** | — |

### 硬约束

- `assay_core` **只依赖 numpy**。不准引入 OpenCV / scipy（沙箱里它们本来就坏，这也是好设计）
- **禁止像素/帧为单位的判定阈值**。空间用 BL、时间用秒，每个阈值配标度不变性测试。
  例外只有传感器噪声底（属传感器属性），且必须进"噪底台账"显式记账，
  **不得被当作判定阈值使用**
- **禁止静默兜底**。本项目 `panel_band` 已经因为静默兜底出过两次事故
  （无行达标时返回整幅高度、取"达标行 min..max"把收集盒夹进来），两次都是全程挑错对象且毫无报错。
  拿不到合理结果就**报警**

### 唯一的输入依赖（DP-022，要先解决）

沙箱 `cv2` 坏、无 `ffmpeg`，**不能解码视频**；但 `numpy` + `PIL` 可用，
所以**上传 PNG/JPG 帧图就能直接分析**。需要从 Mac `~/Work/heavy/depression/悬尾/`
（例 `10mg 2周.mp4`，476×268 / 25 fps / 9661 帧）抽两批全幅帧：

- **A 批**：t ≈ 24 s 挣扎期，连续 8 帧
- **B 批**：t ≥ 240 s 静止期，连续 8 帧

若执行 agent 跑在 Mac 上（有 cv2/ffmpeg），这条依赖自动消失，直接在 Mac 抽帧即可。

## 3. B 轨：人工一致性（DP-012 → DP-013，可立即开工）

**分支**：`feat/human-agreement`，从 `master` 开
**规格**：`docs/SPEC_人工比对与验收_v2.md`（v2.1）§9

### DP-012（第一个 PR）：校验器 + 并集重算。**不算任何一致性指标**

必须实现的四条硬规则：

1. **一律丢弃 `mobile_seconds`**，改用 `union(sorted(holds))` 重算。
   理由：工具每次按键多算约 **0.121 s 墙钟时间**（7 个独立估计 0.110–0.131，CV 6.5%，
   陈璇 7 个 1.0x 试次为决定性证据），进入视频时间时被倍速缩放
2. **读 holds 必须先排序再取并集**。43 个试次里 **12 个** 数组乱序自嵌套
   （王娟 3 / 徐乐彤 5 / 陈璇 3 / 张 1），朴素求和最多虚高 **+54.8 s（+30%）**。
   "只出现在视频组最后一个"的规律**已作废**，出现位置随机
3. **拒绝入库**：`mobile_seconds == 0` 且 `len(holds) == 0` 且 `unscoreable == false`
   ⇒ 报错。这是"没评"不是"评出 0"，按 0 入库会变成 immobility = 360 s（物理上限），
   一个点就拉歪 r 与 Bland-Altman
4. **零长段记账**（张有 3 个），并集口径下自动为 0，无害但要报出来

输出：43 个试次的重算表（每行给 `union` 值、按键段数、是否乱序、是否零长段、倍速、
`presentation_order`）。**不要在这个 PR 里算 r / ICC / Bland-Altman。**

### DP-013（第二个 PR）：LOVO-CV 框架，**先用合成真值跑通，不接人工数据**

```
for 每个视频 v in 7 个视频:
    在其余 6 个视频的试次上拟合 θ_mob（唯一自由参数，
        目标 = 最小化 |软件 immobility − 人工均值 immobility|）
    在 v 的试次上预测，记录样本外结果
汇总 27 个样本外预测 → r / Bland-Altman
```

- **bout 参数保持 FROZEN，不参与拟合。只拟合 θ_mob 一个标量。**
- 框架必须同时输出**每折拟合出的 θ_mob 值本身**——7 个值的变异系数就是 **G2**，
  这是本项目对 CSI 最有价值的一个数字，别只输出汇总 r 就完事

## 4. 提交规程（两轨都适用）

1. 从 `master` 开分支，前缀 `feat/ fix/ chore/ spike/`，**一分支一关注点**
2. commit 首行 `<type>(DP-###): 摘要`
3. `master` 只接受合并
4. **加任何 ignore 规则后必须 `git check-ignore -q <路径>` 实测。**
   ignore 失效是**静默**的——文件在磁盘上，commit 里没有，等要复现验收结果时才发现真值从未入库。
   两个已实测的坑：`data/` 必须写成 `data/*`（带斜杠会让 git 根本不进目录，后面所有 `!` 例外静默失效）；
   unignore 一个目录后**不要再往里加 `**` 规则**（会重新挡住子目录）
5. **沙箱不能 push、不能建 GitHub 仓库、不能用 `gh`**（无 SSH key、`~/.config` 损坏）。
   已确认无解，**不要反复试**。交付靠 `git bundle create <名>.bundle --all`
6. 每个 PR 结束跑 `python3 run_tests.py`，把通过/失败数写进交付说明。**未达标的判据明确写出来，不粉饰**
