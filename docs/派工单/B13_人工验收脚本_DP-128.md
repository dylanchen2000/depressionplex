## 0. 准备（一次性，约 3 分钟）

**0.1 打开工具**：双击 `tools/timer/DepressionPlex_stopwatch_timer_v1.html`（`file://` 直接开，工具零依赖、不联网）。
期望页面顶部第二行：`工具版本 v1.7——请确认打开的是这个版本，旧版会悄悄丢进度。`
（看到 v1.6 就是开错了文件，后面全部不用做。）

**0.2 造验收素材**（全落在 `/tmp`，不碰 `data/`）：

```bash
mkdir -p /tmp/dp128-accept && cd /tmp/dp128-accept
printf 'trial_id,video_filename\nACC-ch1,acc1.mp4\nACC-ch2,acc2.mp4\nACC-ch3,acc3.mp4\n' > acc.csv
for i in 1 2 3; do
  ffmpeg -loglevel error -y -f lavfi -i testsrc=duration=8:size=320x240:rate=15 -pix_fmt yuv420p acc$i.mp4
done
ls -l /tmp/dp128-accept
```

期望：`acc.csv` + `acc1.mp4 acc2.mp4 acc3.mp4`（各约 8 秒）。
清单不带 `assay` 列 ⇒ 工具按 TST 处理；每场窗口 = 录像长度 = 8 秒 ⇒ 评一场只要 8 秒。
（想用真视频也行：把 `acc.csv` 换成 `data/human_scores/manifests/` 里的真清单、视频换成真素材，
**期望文案一字不变**，只有场次名与「还有 N 场没安排」的 N 会不同。）

**0.3 下载目录**：验收会落下 `human_scores_*.csv` 与 `timer_audit_*.json`。
**这些文件不要拷进 `data/human_scores/incoming/`** —— 那会污染真值语料，且 B13 §5 明禁改 `data/`。
建议开工前记一下下载目录里的文件数，之后按时间挑出新生成的那几份。
**把 F1…F6（外加 5C/5D 那两份）都留在同一个目录里别删**：场景 4、5、5B、5C、5D 要手改它们的副本、或同时选好几份。

**0.4 每个场景之间清一次 localStorage**（除场景 6）：DevTools（F12 / ⌥⌘I）→ Console → 执行
`localStorage.clear()`，然后刷新页面。
理由：不清的话 DP-077② 的「本机有存档」二次确认会和「还有 N 场没安排」的二次确认叠在一起，
点击次数会变（这正是场景 6 要观察的现象），把其余场景的期望搅乱。

**0.5 术语**：下文「红字」= 设置区底部的红色提示（`id="setupErr"`）；「弹窗」= 浏览器 alert；
「进度行」= 「已评进度」那一行下面新出现的灰色多行提示（`id="chainStat"`，裁决 1 加的）。
引号里的期望文案都是**逐字**，差一个字就算不通过（Python 侧 `tests/test_timer_tool_contract.py`
已把其中若干句钉死，人工这一遍是核「屏幕上真的是这样」）。
进度行的行数会随情况变（1～5 行），下面每个场景都写清该看到几行、每行是什么。

**0.6 命名约定**：`F1…F6` = 各场景导出的 `timer_audit_*.json`（F1 场景 1、F2 场景 2、F3 场景 3、
F4 场景 5、F5 场景 5B、**F5C 场景 5C、F5D 场景 5D**、F6 场景 7）；`S1…S5` = 各份文件里的 `seed`。
请边做边记，后面场景要用（5C/5D 要同时选 F2/F3/F4，文件名认错了整场就白点）。
**从本版起，每次会话的种子都是当场新生成的**，所以 S1≠S2≠S3≠S4≠S5 是常态，不是故障。

  pass  点完一次之后情况变了 ⇒ 指纹失效，两条内容重新摆出来重读一遍
