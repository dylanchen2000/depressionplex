## 1. node 自测条数：一个来源 + 下限 + 自洽

现在 `tests/test_timer_tool.py::test_stopwatch_timer_js_selftest` 只断言
`returncode == 0` 和「全部通过」四个字，**连条数都不数**。node 自测整体退化成 3 条、
仍然印「全部通过」，这条代理一样是绿的。DP-131 那轮 M43 已经量出「CI 三个 job 对这类错一律是绿的」。

要办的：

1. 断言**印出来的 pass 行数 == 自测自己汇总的那个数**（自洽）。
   只有自洽挡不住整体退化，所以还要第 2 条。
2. 加一条**下限常量**，当前值 **90**，注释写明「加检查时一并上调」。
   只有下限会随时间发霉，两条都要。
3. 这个数字全仓**只许有一处**。`tests/test_timer_tool_contract.py` 里那句
   「node 那 89 条」（DP-131 §6-(13)，5a280cc 当时的真值，现在落后一位）改成引用这个常量，
   不再自带数字。**不许只把 89 改成 90** —— 那样下次加检查还会再落后一位。

守卫要有变异证明：把 node 自测里任意一条 `pass` 删掉 ⇒ 下限那条红；
把汇总数字改成硬编码的大数 ⇒ 自洽那条红；把常量与 docstring 拆回两处各写一个数 ⇒ 也要红。

## 2. 场景 8（界面文案不说假话）搬进契约测试

走脚本 `tmp/acc.md` 场景 8 是一张源码级文案审计表，现在只有我在沙箱里手跑过一遍
（`tmp/acc/s8.py`，逐字计数，不做正则不做归一化）。**原写「16 项」是错的**（凭印象写的，
没跑过数据的数字不许说出口；2026-09-17 按沙箱实测改）：

| 数法 | 实测 |
|---|---|
| 表格数据行 | **15** 行 |
| 左列（期望 0 命中）字符串 | **12** 串（11 串 + `复制种子`，后者按特例单独判） |
| 右列（期望命中）字符串 | **17** 串（12 串「至少 1 处」+ 5 串「恰好 1 处」） |
| `s8.py` 实际判据 | `ZERO` 11 + `ATLEAST1` 12 + `EXACT1` 5 = **28** 条，加 `复制种子` 特例 = **29** 项检查 |

它本来就与
`tests/test_timer_tool_contract.py` 是同一件事：只看源码里那几处不许被悄悄改掉的地方。
靠人手跑，下次改工具就没人再跑。

要办的：把那张表整表搬进契约测试。判据照 `s8.py`，含两处已经踩过的坑：

- **`复制种子` 不是「全文 0 命中」**：源码里有 2 处，都是「按钮已删」的撤回记录
  （更新日志 ⑥、JS 注释）。判据是「每一处都必须落在『删…按钮』的句子里」
  + 按钮本身 0 个 + 渲染正文 0 命中。这与 `按种子全局固定` 只允许以撤回原话形式存在是同一条规矩。
- **不许用出现次数当文案判据**（DP-131 那轮踩过：`请选择视频文件` 从 1 处变 2 处，
  是新写的注释点名了它）。一律锚位置：在哪个锚点之后的哪一块里查。
  已落地的四处 `count == 1` 我核过，钉的都是「代码里那一样东西本身」（按钮标签、`onclick`、
  函数定义、`<select>` 标记），不是会被注释引用的文案，那几处保持；
  **本单新写的一律按锚位置**。

变异证明：左栏任意一句假承诺塞回源码 ⇒ 红；右栏任意一句真话删掉 ⇒ 红；
把 `按种子全局固定` 那处从撤回原话改成一句新承诺 ⇒ 红。
