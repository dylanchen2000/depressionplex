## 1. 根因：`__init__.py` 不能当 PyInstaller 入口脚本（架构问题，不是漏个 import）

`packaging/build_analyzer_windows.spec:17`：

```python
a = Analysis(
    ["../depressionplex/cli/__init__.py"],
```

PyInstaller 把入口脚本**当 `__main__` 执行**，`__package__` 是空的。于是你这一轮加的

```python
from . import _stdio     # __init__.py:14
```

在冻结后必然 `ImportError`——**而且这个错在源码模式下永远看不见**，因为源码模式走的是 `python -m depressionplex.cli`，那条路 `__package__` 是 `"depressionplex.cli"`，一切正常。沙箱里 `run_tests.py` 全绿、`python -m` 全绿，exe 全死。

还有一个更隐蔽的后果，这次没炸但迟早要炸：入口脚本被载成 `__main__` 之后，只要包里任何别的模块 `import depressionplex.cli`，**同一份代码会以 `__main__` 和 `depressionplex.cli` 两个名字各载一次，模块级状态（`SUBCOMMANDS`、`_stdio` 是否已改过 stdout）出现两份**。「一个数字只许有一个序列化器」在模块身上同样成立。

所以修法不是把 `from . import _stdio` 改成 `import depressionplex.cli._stdio`（那只是把这一次的报错按下去，`__main__` 双载还在）。**入口脚本必须是一个专职的、不属于任何包的薄壳。**

### 1.1 必须这么改（C1，最重）

新建 `packaging/analyzer_entry.py`：

```python
"""冻结后端 exe 的入口脚本（PyInstaller 专用，源码模式不走这里）。

不许把 depressionplex/cli/__init__.py 当入口脚本：
- PyInstaller 会把入口脚本当 __main__ 执行，__package__ 为空，
  里面任何 `from . import X` 在冻结后必然 ImportError
  （DP-108 第 12 步实测，run 34826444142）；
- 同一份代码会以 __main__ 和 depressionplex.cli 两个名字各载一次，
  模块级状态出现两份。

本文件只许有 import 和一次 sys.exit(main())，不许有任何逻辑、任何 print。
"""
import sys

from depressionplex.cli import main

if __name__ == "__main__":
    sys.exit(main())
```

`packaging/build_analyzer_windows.spec` 的 `Analysis` 第一个参数改成 `["analyzer_entry.py"]`（spec 的相对路径基准是 spec 所在目录，`pathex=[str(repo_root)]` 保持不动，`depressionplex` 才能被当成真包收进去）。

`depressionplex/cli/__init__.py` 里的 `from . import _stdio` **保持相对不动**——它现在是一个正常的包内模块，相对 import 是对的。

## 2. 第 12 步的 smoke 必须验三条路径，不是一条（C3）

现在的第 12 步只跑 `--help`。上一轮我给的退出码契约是三条：

| 输入 | rc | 输出去向 |
|---|---|---|
| `--help` / `-h` / 无参数 | **0** | 用法到 **stdout** |
| 未知子命令 | **2** | 用法到 **stderr** |
| 内部错误（模块缺 `main` 等） | **1** | 原因到 stderr |

第 12 步改成逐条验，每条都断言 rc **和** 输出内容（PowerShell 里用 `$LASTEXITCODE`）：

```powershell
$exe = "packaging\dist\depression-analyzer\depression-analyzer.exe"

# (1) --help ⇒ rc 0，stdout 里有「用法」
$out = & $exe --help 2>$null
if ($LASTEXITCODE -ne 0) { throw "--help rc=$LASTEXITCODE，应为 0" }
if ($out -notmatch "用法") { throw "--help stdout 里没有「用法」：$out" }
Write-Host "OK --help rc=0, stdout 含中文用法"

# (2) 无参数 ⇒ rc 0
& $exe > $null 2>$null
if ($LASTEXITCODE -ne 0) { throw "无参数 rc=$LASTEXITCODE，应为 0" }
Write-Host "OK 无参数 rc=0"

# (3) 未知子命令 ⇒ rc 2
& $exe definitely-not-a-subcommand > $null 2>$null
if ($LASTEXITCODE -ne 2) { throw "未知子命令 rc=$LASTEXITCODE，应为 2" }
Write-Host "OK 未知子命令 rc=2"
```

**(1) 里对「用法」这两个中文字的断言是这一整轮的核心判据**——它同时证明了 exe 能启动、`force_utf8()` 生效、中文没被 `cp1252` 打死。不许把它换成英文字符串来「让步骤变绿」（共同约定 §3.8）。

`throw` 而不是 `Write-Warning`：**CI 里的 smoke 不许有可跳过的分支**（共同约定 §6）。

## 3. 编码归一化现在有三份实现，收成一份（C4）

| 位置 | 做法 |
|---|---|
| `depressionplex/cli/_stdio.py` | `force_utf8()` |
| `desktop/main.py:21-25` | 自己写了一遍 `io.TextIOWrapper(..., errors="replace")` |
| workflow 里的 inline `python -c` | job 级 `env: PYTHONUTF8: "1"` |

前两份是**同一件事的两份实现**，而且行为不一样：`_stdio.force_utf8()` 与 `errors="replace"` 对不能编码的字符处理不同——外壳会把中文页名印成一串 `?`，**看起来像跑通了，实际上自检输出已经读不出是哪一页**。「静默兜底比报错危险」。

改：`desktop/main.py` 删掉那五行，改成调用同一个 `force_utf8()`，位置仍在所有 print 之前。
第三份（workflow 的 `PYTHONUTF8`）是另一个边界，**保持不动**，理由见共同约定 §6 那一行——不要顺手清理。

守卫：`test_only_one_utf8_shim` —— 全仓（`depressionplex/` + `desktop/` + `packaging/`）grep `TextIOWrapper`，断言只出现在 `_stdio.py` 一个文件里。用**子串**匹配，不许用完全相等（共同约定 §6）。
