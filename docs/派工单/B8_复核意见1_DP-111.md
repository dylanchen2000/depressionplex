## 2. 做对了什么（**不许在后续修改中被「优化」掉**）

这几条是本件的骨架，改动它们等于把资质边界拆了：

1. **`claims_metrology` 只抄不判**：`badge.py:build_badge_view` 里
   `claims = status.may_report_metrology`，模型层自己不判模式。
2. **自相矛盾当场炸**：`(status.badge is Badge.GREEN) != claims` ⇒ `ValueError`。
   这是「界面写着计量模式、导出按研究版声明」这类分叉的唯一硬拦点。
3. **`_STYLES[status.badge]` 用下标不用 `.get`**，新增枚举值忘了配样式就 `KeyError`，
   不会静默退化成某个默认样式。守卫 `test_every_badge_has_a_view` 遍历的是
   `Badge` 枚举本身，不是手抄的清单 —— 这是对的写法。
4. **徽章挂在状态栏、且是 permanent widget**，不是「在结果页放一个」。
   `main_window.py` 的 docstring 把理由写清楚了（状态栏跟窗口不跟页面，
   所以七页连将来新加的页都带着它）。**这个判断是对的。**
5. **控件层零内容**：`widgets/badge.py` 没有中文、没有颜色字面量、没有模式分支，
   `test_widget_holds_no_content` 盯着它。
6. **`_parse` 失败是响亮的**：变异 M4b 往页面里塞了 3.9 编译不过的语法，
   三条守卫立刻红并打印「语法错误」，不是静默跳过。**能被跳过的守卫等于装饰** ——
   这一条它做对了。

## 4. 逐条要求

### R1 `bundled_calibration_path()` 的**目录**必须被验，且要有一次正向往返

**定性：本件最重的洞。** 现在唯一碰这个函数的断言是
`tests/test_badge_view.py:364` 的 `assert path.name == "calibration.json"` ——
只验了**文件名**。M1 / M1b 证明：把目录改成任何别处，12 个测试照样全绿。

**为什么它现在不报错、将来才要命：** 今天仓根没有标定文件、
`EXPECTED_CALIBRATION_SHA256` 是 `None`，所以路径指哪儿都读不到文件 ⇒ 黄徽章 ⇒
`test_end_to_end_with_real_startup_path` 断言的 YELLOW / RESEARCH 照样成立。
**这个测试无法区分「路径对但文件不存在」和「路径压根指错了地方」。**
到 M4 真签发了标定文件、安装脚本按 `{app}\calibration.json` 放好之后，
路径错的后果是：产品**永远认不出自己的资质**，徽章永远黄，
而 CI 全绿、没有任何报错 —— 由客户来发现。
反过来若那时 `EXPECTED_CALIBRATION_SHA256` 已填，路径错会走
`calibration.py` 的「该有却没有」规则 ⇒ **红徽章**，而根因是路径 bug，
不是标定问题 —— 失败归因被抹平成另一件事。

**改法**（`tests/test_badge_view.py`）：

1. 源码模式钉死整条路径：`bundled_calibration_path() == ROOT / "calibration.json"`
   （`ROOT` 测试文件里已有，是独立推导出来的，不许从 `paths.py` 抄）。
2. 冻结模式两条都钉：把 `paths.is_frozen` 打成 `True`、`sys.executable` 指到 tmpdir，
   断言结果 `== Path(sys.executable).parent / "calibration.json"`，
   **`finally` 里恢复**（打补丁不恢复会污染同进程后面的测试 —— 本仓 runner 是单进程）。
3. **正向往返（这条才是「说真话」）**：走冻结分支把 `sys.executable` 指进 tmpdir，
   把 `docs/标定文件示例_研究版.json` 复制到 `bundled_calibration_path()` **返回的那个路径**，
   把 `EXPECTED_CALIBRATION_SHA256` 打成该文件的真 sha256，然后断言
   `status.calibration is not None` 且 `status.calibration.batch` 等于示例里的 batch。
   **这一条证明「写文件的位置」和「读文件的位置」是同一个地方** ——
   名册双向对账，不是只查一个方向。
   （用示例文件不用手搓 payload：`tests/test_calibration_contract.py:226` 已经在防
   这份示例漂移，两边共用同一份就不会各自漂。）

**要求的变异证明**：M1 / M1b 各自必须由本轮新增的断言变红；
往返测试里把示例文件放到派生路径的**上一级目录** ⇒ 必须红。

### R2 三块徽章的文案和免责句必须被逐字钉死

**定性：M2 / M3 已证。** 授予或否认计量资质的那几句话，
现在可以被改成任意别的口径而全套测试不红。
`test_badge_text_exists_in_exactly_one_file` 只断言「别的文件里**没有**这四个字」，
从来没断言 `models/badge.py` 里**有**这四个字；
`test_claims_metrology_mirrors_judgement` 对绿徽章只断言了
「tooltip 里**没有**免责句」这个反方向。**只断一个方向的守卫拦不住换口径。**

**改法**（`tests/test_badge_view.py` 新增一条，用一张表把三块钉在一起）：

| badge | `text` 必须逐字包含 | `claims_metrology` |
|---|---|---|
| YELLOW | `研究用途`、`未计量标定` | `False` |
| GREEN | `计量模式` | `True` |
| RED | `标定不可信`、`已按研究用途运行` | `False` |

外加：`NO_METROLOGY_LINE` 的**值**本身钉一次
（现在全仓只有 `X in view.tooltip` 这种「常量被读到」的用法，
把它改成「本软件功能齐全。」全套照样绿 —— 共同约定 §6「常量被读到 ≠ 值是对的」。
**这一条我没单独跑变异，是从 M2/M3 同族推出来的，按未实测标注**）。
一张表同时封住三件事：换口径、对调文案、把某块的文案清空。

**要求的变异证明**：M2、M3 各自必须红；把 `NO_METROLOGY_LINE` 改成别的句子 ⇒ 必须红。

### R3 模式的二次判定：守卫要从 `ast.Compare` 扩到「任何形状」

**定性：M4 已证。** `test_no_second_mode_decision_in_desktop:339`
只在 `isinstance(node, ast.Compare)` 里找 `VALIDATED` / `RESEARCH`，
所以字典派发（`{Mode.VALIDATED: True}[status.mode]`）完全隐形。
注意 M4 那段注入**不含任何可显示文案**，所以
`test_badge_text_exists_in_exactly_one_file` 也抓不到它 ——
两条守卫的覆盖之间有一条缝，第二个判定器正好从缝里长出来。

**改法**：判据从「Compare 的某一侧」改成「**任何位置**出现
`Mode.VALIDATED` / `Mode.RESEARCH` 属性引用，或出现 `"validated"` / `"research"`
字符串常量（docstring 除外）」，范围 `desktop/` 下除 `services/calibration.py`。
`models/badge.py` 那条严格判据（`test_claims_metrology_mirrors_judgement` 里已经
按「任何 Attribute」查了）**就是正确形状，把它推广到整个 `desktop/`**。
同时覆盖 `ast.Match` 系列节点（`MatchValue` / `MatchAs`）—— CI 是 3.11，
`match` 在那里是合法语法，M4b 在本地 3.9 上编译不过所以没验出来，
**不许因为「本地没复现」就不管**。

**要求的变异证明**：M4 必须红；再往页面里塞一处 `if status.mode.value == "validated":`
必须红。`match` 那条本地跑不了，在 CI 的 `Tests` job 上确认（贴 run id）。

### R4 `bundled_calibration_path` 的调用点要管住，第二个读文件的地方要拦掉

**定性：M5 已证。** `evaluate_calibration` 有单调用点守卫
（`test_calibration_evaluated_in_exactly_one_place`），
但 `bundled_calibration_path` 没有。于是任何页面都能自己派生路径、自己
`json.load` 一遍 —— **绕过哈希校验、绕过降级、绕过 reasons**。
这比第二个判定器更糟：第二个判定器至少还走 `evaluate_calibration` 的规则，
自己读文件的那份连「文件可疑」都判不出来。

**改法**（两条守卫）：

1. `bundled_calibration_path` 在 `desktop/` 里只许被 `main_window.py` 调用
   （照 `evaluate_calibration` 那条的写法）。
2. `desktop/` 下除 `utils/paths.py` 外，**任何代码字符串**都不许出现
   `calibration.json` 字面量（docstring / 注释除外）。

顺带把 `paths.py:21` 那句超前的承诺改准：现在写的是
「**只此一处**：启动自检、签发脚本、安装脚本都引这一个」，
而全仓只有启动自检引它，签发脚本和安装脚本**今天还不存在**。
**文档里的承诺没有守卫就是假承诺** —— 上面第 2 条守卫一加，这句话就变成真的了，
把 docstring 改成指向那条守卫。

**要求的变异证明**：M5 必须红；在任一页面里写 `Path("calibration.json")` ⇒ 必须红。

### R5 `--self-test` 里徽章的运行期证明太弱：`parent() is None` 分不清状态栏和某一页

**定性：这是本件唯一的运行期证明，而它没验到本件的核心主张。**
`desktop/main.py` 新增的那段自检（很好的一段，注释也把「不用 `getattr`」的
理由写清楚了）判的是 `badge.parent() is None`。
但**把徽章挂进任意一个页面的 layout，`parent()` 也不是 `None`** ——
这条断言照样过，而「七页可见」当场就没了。
本件通篇的主张就是「状态栏跟窗口不跟页面，所以七页都带着它」，
偏偏这一条没被验。AST 那边只能看见代码里写了 `addPermanentWidget`
（`test_main_window_wires_badge_into_status_bar`），看不见它挂到了哪儿。

**改法**（`desktop/main.py` 的 `self_test()`）：

- 断言 `window.statusBar().isAncestorOf(badge)`。
  用 `isAncestorOf` 而不是 `badge.parent() is window.statusBar()`：
  前者是文档化的 API，即使 Qt 在中间塞了容器也成立，
  而它同样能把「挂在状态栏」和「挂在某一页」区分开 —— 这正是要区分的那件事。
- 断言 `view.text` 非空（运行期兜一道，成本一行）。
- 现有那条 `claims_metrology` 与 `may_report_metrology` 一致的断言**保留**，很好。

**要求的变异证明**：把 `addPermanentWidget(self.mode_badge)` 改成挂进
`central` 的 layout ⇒ `Desktop Self-Test` 两个平台都必须红（贴 run id）。
这条**必须在 CI 上验**，沙箱没有 PySide6（共同约定 §4：
任何关于桌面页面能否构造的结论只认 `desktop-selftest`）。

### R6 免责文案两处受众 —— 裁决：允许两份文本，但判定必须单源（**划给 #96 闭环，本轮不改**）

`models/badge.py` 的 `NO_METROLOGY_LINE` 是**屏幕上**的免责句；
导出层（`feat/dp110-export`）的报告声明是**纸面上**的声明，两者受众不同、
篇幅要求不同，**允许是两份文本**，不强行合成一份。

**但判定不许有两个来源**：报告里印不印计量声明，必须由
`may_report_metrology` 驱动，不许导出层自己再判一次模式。
**这一条我在复核 #96 时逐条验，DP-111 本轮不动导出层的任何文件。**

### 我自己那条守卫也有洞，是它自己的变异测出来的

R4 守卫第一版判据是「`ast.Call` 里 `func` 是 `ast.Name(id="bundled_calibration_path")`」。
补齐之后重跑，**M5 依然全绿** —— 因为那段注入写的是
`from ...paths import bundled_calibration_path as _bcp`，调用点的 Name 是 `_bcp`。
**一行别名就绕过了。**

改法：判据从调用点挪到 **`ImportFrom` 的原名**上（别名随便起，原名改不了），
三种形状全收（`from x import target [as y]` / `x.target` / 裸 `target`），
顺手把 `evaluate_calibration` 一起纳进来 —— A 原来那条
`test_calibration_evaluated_in_exactly_one_place` 有**同一个别名洞**。
那条保留不动（它没错，只是窄），新守卫从 import 上把两个入口一起钉死。

这件事本身是共同约定 §6 的实例：**守卫写完必须自己踩一遍**，
不然「加了守卫」和「拦得住」是两件事。
