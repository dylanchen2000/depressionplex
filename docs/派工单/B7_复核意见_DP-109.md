## 1. 必须改

### H1（最重）`acq_check_argv` 本单删掉，argv 拼装留给 B10

`desktop/app/services/engine.py:127-152`。六个问题，任何一个单独都够退回：

1. **它是仓里第四个 `is_frozen`，而且答案和另外三个不一样。**
   `desktop/app/utils/paths.py:22` 是权威版：`getattr(sys,"frozen",False) **and** hasattr(sys,"_MEIPASS")`；
   `engine.py:87` 与 `engine.py:120` 各内联抄了一份（这两处是既有债，DP-112 记着）；
   你新加的第 142 行是 `getattr(__import__("sys"), "frozen", False)`——**把 `_MEIPASS` 那半边丢了**。
   后果不是风格问题：`sys.frozen` 为真而 `_MEIPASS` 不在的环境里，`acq_check_argv` 走冻结分支、
   `engine_command()`（第 120 行判的）走源码分支，拼出来的是
   `[python, -m, depressionplex.cli.analyze, acq-check, --video, …]`——**用 analyze 的 CLI 吃 acq-check 的参数**。
   同一次调用里，「冻结了吗」有两个答案。**一个门槛只许有一个来源**，这条在本仓已经栽过三次。
2. **`__import__("sys")` 是绕过静态守卫的写法。** 就算你不是故意的，形状就是这个：任何找 `sys.frozen` 的 AST/grep 守卫都看不见它。
3. **`cmd[:-1] + [...]` 靠切片猜 `engine_command()` 的返回形状。** 它今天返回三元素所以能跑；B10 一改（加个 flag、换个形式），切掉的就是别的东西，而拼出来的命令**照样能执行**——错得不报错。
4. **冻结分支猜的是一个还不存在的约定。** 你自己的注释写着「dp-engine 接受 acq-check 子命令（B10 约定）」——B10 的 PR #95 还没合，那个子命令**现在不存在**。这是「未知不许长成一句确定的判断」的 argv 版。
5. **没有任何测试碰过它**（我 grep 了整仓）。
6. **没有任何调用者**：`pages/self_test.py:93` 写着 `TODO B10+：用 engine.acq_check_argv 起子进程`。

一段没调用者、没测试、还猜了别人未来约定的 argv 拼装，比不写更糟——**B10 合入后会有人把它当成「已经做好了」直接接上**。

裁决：

- 本单**删掉 `acq_check_argv`**。argv 在 B10/B11 那边做，那时才知道打包出来的 exe 真的接什么子命令，也才能配守卫对账。
- 顺手把 `engine.py:87` 与 `engine.py:120` 两处内联改成 `from desktop.app.utils.paths import is_frozen`（你已经在改这个文件，这是最省事的时候）；
- 加一条 AST 守卫：**`desktop/**` 里除 `utils/paths.py` 外，不许出现 `sys.frozen`、`_MEIPASS`、`__import__("sys")`**。这条同时把第 2 点那个旁路堵死。
- `packaging/engine.py` 里那份留给 DP-112（B10 合入后我做）。

### H2 结论区在「量不了」的时候是一片空白

`pages/self_test.py:186-227`。`contrast_passed` 为真、`area_jitter_passed` 为 `None`（抖动这一项没测出来）时：

- 三条报警都不触发（`contrast_passed is False` 假、`moving is True` 假、`contrast_value is None` 假）；
- 进 `if not lines:` → `if r.contrast_passed and r.area_jitter_passed:` 得到 `True and None` = `None`（假）→ `elif ... is False:` 也假 → **一个分支都不走**；
- `setText("")`。

于是客户看到：表里几行 `—`，**结论区一个字都没有**。而这一页的全部产品价值就是最后那句结论。
`area_jitter_moving is None` 同理沉默。你在「无面板带」那条上写得非常对——「这不是『不达标』，是『量不了』」——但只写了对比度那一个门。

裁决：三个门每一个都是**通过 / 不通过 / 量不了**三态，任一为「量不了」必须出一句话；结论区**永不为空**。

而且这条守不住，因为页面要 PySide6、`Tests` 里跑不到。所以：

**把「读数 → 结论句列表」抽成 `models/self_test.py` 里的纯函数**（`conclusion_lines(result) -> list[str]`，纯标准库），
页面只负责 `"\n\n".join(...)`。然后穷举三态组合（3 个门 × {True, False, None}，27 种）断言**每一种都至少有一句话**。
纪律和 B6 那边是同一条：**判断在模型层，摆放在页面层**。

### H3 三个门槛常量里只有一个有「真的被读」的守卫

守卫 2（`test_gate_constants_actually_affect_judgment`）的做法是对的——临时把常量改成 `1e9`，看判定是否翻转。
问题是它**只 patch 了 `GATE_CONTRAST_ABS`**。我的实测：

| 变异 | 结果 |
|---|---|
| M1 `(b / max(d,1e-9)) >= GATE_CONTRAST_RATIO` → `>= 2.0` | **没红（装饰）** |
| M5 `jitter_best <= GATE_AREA_JITTER_P90` → `<= 1/50` | **没红（装饰）** |
| M2 abs 那半边写回 `100.0` | 红 1（守卫 2） |
| M3 abs 那半边写成整数 `>= 100` | 红 1（守卫 2） |

M5 顺带证明了一件事：**「查字面量」这条路本身可绕**——`1/50` 是 BinOp 不是 Constant，字面量黑名单看不见它（`float("0.02")`、`0.019999999999999998` 同理）。
所以正解不是把黑名单加长，而是把守卫 2 的做法**给三个常量各配一条**：patch 常量 ⇒ 判定必须翻转 ⇒ 还原 ⇒ 复验基线（你现在这条已经有还原后复验，写法对，照抄）。这三条一上，M1 和 M5 都会红。

### H4 守卫 1 的豁免太宽 + `segment.py` 根本不在检查范围

`tests/test_acq_check.py:137`。两个洞，都实测过：

1. **模块级 `NAME = <字面量>` 一律豁免**。我在 `acq_check.py` 模块级加了一行 `MY_ABS: float = 100.0`——
   **M4b 没红**。也就是说：这条守卫要消灭的那个第二来源，**换个名字放在模块级就能原样长回来**。
   （放在函数体里会红，M4 红 1——因为豁免只收 `tree.body`。所以它防的是最不像的那种写法。）
   改法：豁免写死白名单，**只有 `probe_frames.MOVING_RESIDUAL` 一个**，并要求它旁边有理由注释（你已经写了，很好）。
2. **`segment.py` 不在 `check_files` 里**——而它既是三个常量的定义处，**又是 `contrast_report` 的判定处**。
   门槛判定所在的那个文件，一个字面量都没人查。这就是 H3 里 M1 能活下来的原因之一。
   `segment.py` 要进 `check_files`（用白名单豁免它自己那三行定义）。

### H5 键集有两份名册，没有任何守卫对账，而且现有的守卫是单向的

- 引擎侧：`acq_check.ACQ_JSON_KEYS` / `ACQ_VIDEO_KEYS` / `ACQ_SAMPLING_KEYS` / `ACQ_GATES_KEYS` / `ACQ_CONTRAST_KEYS` / `ACQ_NOISE_FLOOR_KEYS` / `ACQ_AREA_JITTER_KEYS`；
- 桌面侧：`desktop/app/models/self_test.py` 里六个手抄的元组（`_require_keys(...)`）。

实测：

| 变异 | 结果 |
|---|---|
| M7 桌面元组**少**一个键（`moving`） | **没红（装饰）** |
| M9 桌面元组**多**一个键（`spam`） | 红 1（端到端守卫） |

少一个键的后果比多一个重：桌面**不再要求**引擎给这个键，于是引擎哪天不给了也没人红，
页面在 `self._data["gates"]["area_jitter"]["moving"]` 处 `KeyError` ——而页面只接 `AcqCheckError`，这个会穿透到 Qt 事件循环。

镜像本身是合理的（进程边界决定桌面不许 import 引擎，这点你判断对了，见 §2），但**镜像必须有守卫**。
加一条：AST 解析 `desktop/app/models/self_test.py` 里那六个元组，与 `acq_check.ACQ_*_KEYS` **逐字相等**。
同型先例照抄 `tests/test_desktop_boundary.py::test_dependency_table_in_spec_matches_pyproject`（DP-114）。

### H6 同一份 JSON 有四个构造点，键集守卫只对账走到的那一条

`acq_check.py` 行 **127 / 183 / 291 / 364** 各手抄了一遍整个输出骨架。我 AST 比过，**今天这四份键完全相同，没有活着的 bug**——
但守卫 3 只在 rc=0 那条路上逐层对账。另外三条是 rc=2：**「客户的设备有问题」时才走的路**，也就是这一页最要紧的那几条。
往 `ACQ_VIDEO_KEYS` 加一个键、四处改了三处，第四条路就返回一份缺键的 JSON，而 CI 全绿。

改法：合并成一个 `_build_output(...)` 构造点（未知一律显式传 `None`），四条出口都调它；键集守卫**覆盖四条出口**。

### H7 冻结参考读数不许寄生在 `docs/STATUS.md` 上

守卫 8 从 `docs/STATUS.md` 正则抓 P2 读数。三个问题：

1. **STATUS.md 按公司规范是「每次收工覆盖写的快照，不是日志」。** 它被重写、那张 P2 表被挪走的那一天，这条守卫就红，
   而压力下的下一步永远是删守卫。**把测试套件挂在一份设计上就要被覆盖的文件上，是把守卫交给下一次收工去删。**
2. **`m_nf` 捕获了值但从未比较**（`m_nf.group(1)` 一次都没用），它只证明文档里存在**某个** `**N px**`。这是死断言。
3. `0.43` 与 `0.0035` 在测试里各自又写了一份字面量 ⇒ **每个数字三份拷贝**（文档 / fixture / 测试），
   正则里还嵌着 `≥100`、`≥2×`（门槛值的第四份）。

裁决：`tests/fixtures/p2_reference.json` 是**唯一权威**（它已经带 `measured_at`、`decoder`、`sha256: null` 三态，做得对），
对账目标改成 `docs/ISSUES.md`（append-only 台账，不会被覆盖写）——把 P2 那四个读数连同「素材不在仓里」的说明补一行进去。
守卫按和 B6 同一个形状写：**从 fixture 的键循环**，每个读数必须有来源、来源文件必须存在、值必须在该文件里出现；测试里不留字面量。
