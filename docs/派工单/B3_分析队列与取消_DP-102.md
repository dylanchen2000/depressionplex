> **分支（写死，不许自己改名）**：`feat/dp102-analysis-queue`
> **基线**：`integration/product-base`
> **上游**：B1（外壳骨架，已交付）、B3a（引擎的 `--progress-json` / `--run-json`，已交付）、

## 1. 背景：为什么必须是子进程

架构 §3.4：GUI 与引擎之间是**进程边界**，不是线程边界。三条理由，每条都花过钱：

- **取消要干净**：长解码里的取消，杀进程是唯一可靠的；线程里的取消要么靠标志位（引擎里
  没有、也不许加，见共同约定 §3.4）要么靠强杀线程（Python 不支持）。
- **崩了不带走 GUI**：解码段崩溃只死子进程，队列还能继续跑下一条。
- **验收判据自动成立**：GUI 跑出的 CSV 与 `cli/analyze.py` 直跑**逐位相同**——因为跑的
  就是同一个 CLI。你要做的只是**别在外壳里再算一遍任何数字**。

所以本单的核心不是 UI，是**把命令行拼对、把 stderr 读对、把取消收拾干净**。

## 2. 要做什么

### 2.1 引擎命令的解析（`desktop/app/services/engine.py`，只用标准库）

```python
def engine_command() -> list[str]:
    """引擎调用前缀。冻结与源码两种情形。"""
```

- **源码运行**：`[sys.executable, "-m", "depressionplex.cli.analyze"]`，子进程 `cwd` 设为仓根
  （`paths.resource_path("..")` 的上一级；`-m` 需要仓根在 cwd 上，不许用 `sys.path` 魔法）。
- **冻结**（`paths.is_frozen()`）：与主程序**同目录**的 `dp-engine.exe` / `dp-engine`。
  名字写死 `dp-engine`，B10 的打包 spec 要按这个名字产出（本单只管按名字找，找不到就报错）。
- **环境变量 `DPX_ENGINE_CMD` 优先**（用 `shlex.split` 解析），给测试与现场排障用。
- 找不到可执行文件时**当场报错并说清找了哪个路径**，不许静默退回 `python`
  （客户机上的 `python` 可能是另一个环境，那会跑出一份来路不明的数字）。

### 2.2 命令行拼装（同文件，**纯函数**）

```python
def build_argv(exp: dict, video_index: int) -> list[str]:
    """按 experiment.json 契约（DP-101 §2.1）拼一条视频的完整 argv。"""
```

每条视频**必须**带满这五个输出/开关参数，缺一个下游就瞎：

| 参数 | 值 | 缺了会怎样 |
|---|---|---|
| `--csv` | `<output_dir>/<视频名去扩展名>.csv` | B4 没数字可读 |
| `--timeline-csv` | `<output_dir>/<视频名去扩展名>_timeline.csv` | B5 没段可看 |
| `--run-json` | `<output_dir>/<视频名去扩展名>_run.json` | B4 没报警行、B6 没 θ_mob |
| `--progress-json` | 开关 | 进度条只能瞎转 |
| `--assay` / `--chambers` / `--calib-frames` / `--trial-prefix` / `--body-area-prior` | 从 `experiment.json` 取；为 `null` 的**整个参数不传**（不许传空串、不许传 `None` 的字面量 `"None"`） | 传空串会让引擎把空串当前缀 |

路径一律绝对；同名文件已存在时**不许覆盖**，整条 item 直接置失败并说明（客户重跑同一批
最容易在这里悄悄盖掉上一轮的数字）。

### 2.3 stderr 进度（`desktop/app/services/progress.py`，只用标准库，**纯逻辑**）

引擎往 stderr 写两种东西，**都要收**：

- 进度行：`{"ev": "progress", "frame": 1234, "n": 45000}`，`n` 可能是 `null`（总帧数未知）。
- 其它行：`[警告] …` 这类人话（例如版本号取不到）。**不许丢**，进日志与该 item 的详情。

要求：

1. 一个有状态的行缓冲（`class StderrPump`）：QProcess 给的是**字节块**，一次可能给半行、
   也可能给三行。半行必须缓着等下一块，**不许当坏行报错，也不许丢**。
2. `n` 为 `null` ⇒ **不确定进度条**（`QProgressBar` 的 `setRange(0, 0)`），文字写「已处理 1234 帧」。
   `percent(frame, None)` 必须返回 `None`，**不许算出 0% 或 100%**，不许除以 `n`。
3. 解析不出的行照原样进日志，**不许拿它当进度**、不许静默 `pass`。
4. 引擎的 **stdout 是给人读的报告**：整条存成 `<output_dir>/<视频名>_report.txt`。
   **B4 不许解析它取数字**（数字读 CSV / run.json）——这行写进你的 PR 正文，B4 会照抄。

### 2.4 队列页（`desktop/app/pages/queue.py`，替换 B1 占位页）

- 类名仍 `QueuePage`，`PAGE_ORDER` 不动；`placeholders.py` 里的旧 `QueuePage` **删掉**
  （两个同名类会让「哪个被用」取决于 import 顺序）。页面守卫的改法与 B2 同（见 DP-101 §4.2；
  两单都改到同一处时后合的那个负责解冲突，**只许变严**）。
- **必须用 `QProcess`**，不许 `subprocess` + 线程（QProcess 的 `readyReadStandardError`
  天然不阻塞事件循环；线程方案会在 Windows 冻结后出现读不完的管道死锁）。
- **串行**：`MAX_CONCURRENT = 1`，写成常量。M1 不许暴露并发数控件
  （并行解码会把 I/O 打满、让每条的进度都失真，也让内存峰值不可预测）。
- 每条 item 六个状态，**一个都不许合并**：
  `待跑` / `运行中` / `完成` / `无产出` / `失败` / `已取消`。
  退出码映射写死（引擎的约定，见 `cli/analyze.py` 顶部 docstring）：

  | 退出码 | 状态 | 界面上要说的话 |
  |---|---|---|
  | 0 | 完成 | 出了几个隔间的数字 |
  | **2** | **无产出** | 跑完了，但一个隔间都没产出数字；原因读 `run.json` 的 `not_scored` 逐条列出 |
  | 1 | 失败 | 解码/探测失败，贴 stderr 最后几行 |
  | 其它 / 被信号杀 | 失败 | 同上 |

  **`2` 不许映射成失败、更不许映射成完成**：它是「跑通了但按判据不放行」，
  是本产品最要紧的一种正常结果（排除态隔间不产数字，DP-028）。
- **取消 = 杀进程**：`terminate()`，超时（建议 3 s）后 `kill()`。取消后：
  1. 该 item 置 `已取消`；
  2. **删掉这条 item 自己的半成品输出**（`--csv` / `--timeline-csv` / `--run-json` /
     `_report.txt` 四个路径，只删这四个，**不许按通配删目录**）；
  3. 队列停在那里，不许自动跑下一条（客户按取消是想停下来看看）；
  4. 状态机里**不许存在 `已取消 → 完成` 的迁移**。
- 队列状态落盘：`user_data_dir(create=True)/queue_state.json`，每次状态变化后写一次。
  **不许写缓存目录**（`user_cache_dir` 不许放唯一副本）。崩溃重启后至少能看出哪几条跑完了。

## 3. 测试（新建 `tests/test_queue_contract.py`，登记进 `run_tests.py`）

测试环境**没有 PySide6**，所以 `engine.py` / `progress.py` / 状态机与退出码映射
**不许 import PySide6**（放 `services/` 与 `models/`，Widget 只做接线）。
测试一律 AST 静态解析或直接调纯函数，**不许 import `desktop.app.pages.*`**。

必须有这几条，每条都要被变异测试打红：

| 守卫 | 断言 |
|---|---|
| 五个参数一个不缺 | `build_argv` 的产出里必须同时有 `--csv` / `--timeline-csv` / `--run-json` / `--progress-json` / `--assay` |
| 旗标真的存在 | AST 取 `depressionplex/cli/analyze.py` 全部 `ap.add_argument("--x")` 旗标，断言 `build_argv` 用到的每个旗标都在里面（拼错一个字母就红） |
| `null` 不传参 | `trial_prefix` / `body_area_prior` 为 `null` 时，argv 里既没有该旗标也没有 `"None"` / `""` |
| 路径全绝对 | argv 里每个路径参数 `Path(p).is_absolute()` |
| 不覆盖已存在输出 | 目标 CSV 已存在时，构造 item 就报错（不许跑起来再说） |
| 半行能拼回来 | `StderrPump` 分三次喂 `{"ev":"pro`、`gress","frame":7,"n":null}`、`\n{"ev"…` 能正确产出两条 |
| 非进度行不丢 | 喂 `[警告] 版本号取不到\n` ⇒ 归为日志行，**不是**进度、**不被**丢弃 |
| `n=null` 不算百分比 | `percent(7, None) is None`；且喂 `n=null` 的进度行不许让任何算术抛异常 |
| 退出码映射 | `status_for_exit(0)=="完成"`、`status_for_exit(2)=="无产出"`、`status_for_exit(1)=="失败"`、`status_for_exit(9)=="失败"`；**`2` 单独一条测试，注释写明它不是失败** |
| 状态机 | `已取消` 之后不许迁到 `完成`（调用即抛） |
| 取消只删自己的四个文件 | 造一个目录放六个文件（四个属于本 item、两个属于别的 item），取消清理后剩下且只剩那两个 |
| 串行写死 | `MAX_CONCURRENT == 1`，且 `queue.py` 里不许出现任何把它变成控件的代码（AST：这个名字不许出现在赋值右侧以外的地方） |

## 5. 本单特有的禁令

1. **不许在外壳里算任何数字**：不许解析 stdout 取秒数、不许自己累加帧数换算时长、
   不许重算 immobility。外壳只搬文件、只显示。
2. **不许在外壳里解码视频**（含 `QtMultimedia`）。引擎是唯一解码器。
3. **不许 `subprocess` + 线程**读管道；用 `QProcess`。
4. 不许做协作式取消（不给引擎加标志位、不看回调返回值）。取消就是杀进程。
5. 不许把退出码 `2` 当失败或成功；不许把「被杀」当完成。
6. 不许 `try/except: pass` 吞任何子进程错误；每一种失败都要在界面上说出人话。
7. 不许改 `depressionplex/`、`.github/workflows/`、`desktop/main.py` 的自检判定。
8. 不许 `git add -A`。
