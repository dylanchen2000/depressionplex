## 1. 必须改（第三轮验收项）

### B1. `analyze._write_csv` 不存在，端到端守卫在任何机器上都跑不起来

`tests/test_report_model.py:659` 调 `A._write_csv(csv_path, rows)` → `AttributeError: module 'depressionplex.cli.analyze' has no attribute '_write_csv'`。

这条守卫的名字叫 `test_end_to_end_with_real_engine_output`——它是这个文件里最吃重的一条（真引擎输出能不能一路走到报告）。它必须**真的跑起来**。

三条路，只许走第三条：

| 走法 | 裁决 |
|---|---|
| 在测试里自己拼 16 字段 CSV | **不许**。那是第二个 CSV 写入器，格式一分叉就再也说不清客户拿到的是哪一份 |

产品里外壳就是起子进程读文件（架构 §3.4），端到端守卫必须和产品同一条路。

### B2. 删掉 `pyproject.toml` 里的 `export = ["openpyxl>=3.1"]`

DP-114 已裁决：**外壳第三方依赖的唯一权威清单是 `desktop` extra**，版本必须钉死，并且在
`[tool.depressionplex.desktop-imports]` 里声明 import 名和允许出现的位置。main 上现在是：

```toml
desktop = ["PySide6==6.7.3", "openpyxl==3.1.5"]

[tool.depressionplex.desktop-imports]
PySide6 = { module = "PySide6", scope = "*" }
openpyxl = { module = "openpyxl", scope = "desktop/app/services/export_xlsx.py" }
```

你加的 `export` extra 是第二份清单，而且写成 `>=`。`>=` 的后果不是「宽松一点」，是**客户手里那个 .xlsx 由一个我们没测过的库写出来的字节**。删掉它，需要什么就改 `desktop` 那一份。

顺带：`import openpyxl` 现在只许出现在 `desktop/app/services/export_xlsx.py`。你目前正是这么写的（模块顶层 import，没散出去），这点我核了，通过——别在第三轮为了「懒加载」把它挪到函数里，那样白名单守卫查不到位置。

### B3. PDF 这条路，在任何 CI 上都没有被执行过一次

- `Tests` 里没有 PySide6（这是刻意的，`test_no_pyside_import_in_tests` 守着），所以 `render_pdf` 永远跑不到；
- `desktop-selftest.yml` 只装 `PySide6==6.7.3`，而 `desktop/main.py` 的自检里**一个 export/report 字样都没有**；
- `export.py:105` 是函数内懒 import，所以连「导出层能不能被 import」都没有任何机器验过。

也就是说：**客户拿走的那份 PDF，我们从没在任何机器上渲出来看过一眼**。客户点「导出…」那一刻才是第一次。

第三轮必须补：在 `desktop-selftest.yml` 里加一步，`QT_QPA_PLATFORM=offscreen` 真渲一份 PDF + 一份 xlsx，并断言

1. 文件存在且非空；
2. PDF 头四字节是 `%PDF-`；
3. PDF 与 xlsx 里都出现声明文案（研究版那段，架构 §4）——三份输出同一个声明来源，你已经有 `test_declaration_same_source_in_all_three_outputs`，把它的 PDF 半边真的跑起来。

这一步要 `pip install openpyxl==3.1.5`（版本与 pyproject 逐字一致）。装的时候注意：`test_ci_installs_the_pinned_desktop_deps` 目前只对账 `tests.yml` + `desktop-selftest.yml` 里的 PySide6 pin，你在 selftest 里新增 openpyxl 后**要把它也纳入对账**，否则将来有人改 pyproject 的 pin，这一步会静默留在旧版本上。

### B4. 文件头写 QPdfWriter，代码 import 的是 QPrinter

`export_pdf.py` 开头写「**不引入第三方 PDF 库**：QPdfWriter 是 PySide6 自带的」，
`export_pdf.py:238` 却是 `from PySide6.QtPrintSupport import QPrinter`。

两个后果：

1. 文档说 A、代码做 B，中间没有任何守卫对账——**注解不是校验**；
2. `QtPrintSupport` 是独立模块，`QPrinter` 的 PDF 输出在冻结打包（DP-108）后要带 printsupport 插件，Linux 上还会牵到 CUPS；`QPdfWriter` 在 `QtGui` 里，无插件依赖，离屏渲染也更稳。

裁决：**改用 `QPdfWriter` + `QTextDocument`**，注释改成事实。如果你有理由坚持 `QPrinter`，那就给证据——冻结后的 Windows exe 上真的渲出一份 PDF，我按证据判。

### B5. 验证读数的名册只盖住 6/16，而 SOP 那半段还能被整段跳过

csi_n  csi_r  csi_bias_s  csi_mae_s  csi_empty_cup_s  csi_empty_cup_pct

其中 `csi_r = "0.842"` 是 **G7 门槛 0.818 的来源**，是整个产品对外声明里最吃重的一个数字；
`csi_empty_cup_s / _pct` 是空杯那条 G10a 声明的根据。这些印在客户拿走的报告上，却没人对过账。

另外两处：

- `if sop_path.exists():` —— **能被跳过的守卫等于装饰**。SOP 从 `v1.5` 改名成 `v1.6`，这半段就整段静默跳过。这不是假想：道俊已确认标注工具 v1.6 已发给同事并在用，文档跟着改名是迟早的事。

正解（第三轮按这个写）：**守卫的名册从 JSON 自己的 `__sources` 长出来**，不许在测试里手抄子集——

1. 逐键循环 `readings` 里除 `__comment` / `__sources` 外的每一个键；
2. 每个键必须在 `__sources` 里有条目，**没有就红**（反向断言：一个读数没写来源，立刻红——坏掉的名册不许长成一份空名册）；
3. 从来源串里取**文件名**，文件不存在**就红**（不许 `if exists()`）；行号只当给人看的注释，不参与匹配（行号一定会漂）；
4. 值的字符串形式必须出现在该文件里，不出现就红。

这样加一个读数、改一个文档，守卫自己会说话，测试里也不再存第三份数字。
