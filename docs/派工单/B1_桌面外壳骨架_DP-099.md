## 1. 背景（一句话：先把「能被 CI 验」的空壳立起来）

产品最终形态是 Windows 桌面 .exe。**沙箱里跑不起任何 GUI 代码**
（`pip install PySide6` 时 pip 自身报 `OSError: [Errno 5]`，而且无显示），
所以 **GitHub Actions 是外壳的唯一执行者**。B0 已经把 CI 建好并转绿：
`.github/workflows/desktop-selftest.yml` 会在 ubuntu(offscreen) + windows-latest 上装
PySide6 6.7.3，然后**当 `desktop/main.py` 存在时**执行

```bash
python -m desktop.main --self-test
```

现在那一步会打印「`desktop/` 尚不存在，已跳过自检（B1 未交付）」。
**这一单的成败就是：让这条命令在两个平台上真的跑起来并退出码 0。**

### 2.4 `--self-test`（本单的核心，判据就靠它）

`main.py` 要能这样跑：

```bash
QT_QPA_PLATFORM=offscreen python -m desktop.main --self-test    # 仓根为 cwd
```

行为：
1. 建 `QApplication`（**不许 `show()`、不许 `exec()`、不许弹任何模态框**）；
2. 构造 `MainWindow`，**逐个构造全部七个页面**（不是只建当前页——只在切页时才构造的页面等于没被验过）；
3. 打印一份**机器可读又人可读**的清单，至少含：PySide6 版本、`QT_QPA_PLATFORM`、
   七个页面各自的类名与构造耗时（毫秒）、`user_data_dir()` 的实际路径、总启动耗时；
4. 最后一行固定打印 `SELF-TEST OK pages=7 total_ms=<数>`；
5. `return 0`。任何一步抛异常 ⇒ **让它抛出去**（退出码非 0），
   **不许 `try/except` 兜住后仍然打印 OK**。

不带 `--self-test` 时是正常 GUI 行为（`show()` + `exec()`）。

### 2.5 守卫测试 `tests/test_desktop_boundary.py`（**沙箱里必须能跑**）

**只许用 `ast` 静态解析源码，绝对不许 import 任何 `desktop.*` 模块或 PySide6**
——本仓测试套件跑在没有 PySide6 的环境里（`run_tests.py`，非 pytest）。四条：

1. **进程边界**：`desktop/**/*.py` 里不允许出现任何 `import depressionplex` /
   `from depressionplex(.…) import` /  `import assay_core` / `from assay_core…`。
   （架构文件 §3.4：外壳与引擎之间是进程边界，外壳只起子进程 + 读文件。）
2. **依赖白名单**：`desktop/**/*.py` 的顶层第三方 import 只允许 `PySide6`；
   其余必须是标准库（用一份显式白名单，命中不在名单里的名字就报错并打印出文件名与行号）。
3. **禁 `sys.path` 魔法**：`desktop/**/*.py` 里不允许出现 `sys.path` 的赋值/`insert`/`append`。
4. **入口对齐 CI**：`desktop/main.py` 里必须出现 `--self-test`，且
   `.github/workflows/desktop-selftest.yml` 里必须出现 `-m desktop.main --self-test`
   ——**两边任何一边改了名字，这条测试就该红**。

四条都要**能独立失败**：写完后逐条临时破坏一次，确认它真的会红（在交付报告里说明你怎么验的）。
**不许写 `if not path.exists(): return`** 这种可被跳过的守卫（本仓吃过三次这个教训：
DP-069 / DP-071 / DP-076），文件不在就直接 `assert` 失败。

新测试模块要注册进 `run_tests.py` 的 `TEST_MODULES`，否则元守卫 `test_run_tests_registry` 会红。

## 4. 怎么验收（缺一条即退回）

## 5. 不许做什么

1. **不许 import 本仓的分析包**（`depressionplex` / `assay_core`），一行都不许 —— 这是架构边界，
   不是风格偏好。需要跑分析是 B3 的事，走子进程。
2. **不许在外壳里算任何指标**（秒数、分母、比例、阈值判定一律不许）。
3. **不许改 `.github/workflows/` 下任何文件**（B0 已交付并转绿；要改就先来问我）。
4. **不许改 `desktop/app/styles/` 下已存在的两个文件**。
5. **不许改包内任何代码**（`depressionplex/**`）、不许动测试基线、不许改 `pyproject.toml` 的依赖约束。
6. **不许在 `--self-test` 路径上 `show()` / `exec()` / 弹模态框 / 开线程 / 读注册表 / 联网**
   —— 任何让自检命令跑不通的写法一律拒收（架构文件 §3 第二条铁律）。
7. **不许用 `try/except` 兜住自检里的失败**后仍打印 OK；不许给 workflow 加 `continue-on-error` / `|| true`。
8. 不许引入 PySide6 以外的第三方依赖（**不许 onnxruntime / opencv / torch / scipy**）。
9. 不许打包字体 .ttf（已核实 `dark.qss` 无 `url(...)`、字体全带 fallback，本单不需要）。
10. 不许 `git add -A`；不许把含 token 的 remote URL 写进任何文件、日志、commit message 或 PR 正文。
11. **不许为了让本单「看起来过了」而放宽判据**（例如把判据改成「YAML 语法正确」「本地能起窗」）。
    **没在 Actions 上双绿就是没验收，照实报。**

## 附：工作区隔离（**先做这一步，否则会和另一个 agent 抢同一个 checkout**）

B1 与 B3a 同时在跑，**同一个 git 工作树不能被两个分支同时占用**。
所以你**不许**在主目录里 `git checkout`，而是给自己开一个独立 worktree：

```bash
R=/home/node/a0/workspace/2315a51b-85c4-46a5-bffe-146b458fd5b6/workspace/depressionplex
git -C $R fetch origin
git -C $R worktree add /home/node/a0/workspace/2315a51b-85c4-46a5-bffe-146b458fd5b6/workspace/wt-b1 \
    -b feat/dp099-desktop-skeleton origin/integration/product-base
cd /home/node/a0/workspace/2315a51b-85c4-46a5-bffe-146b458fd5b6/workspace/wt-b1
```

- **基线分支是 `origin/integration/product-base`**（= main + B0 的 CI + 架构文件 + 已搬入的皮肤）。
  不是 `main`：main 上还没有 workflow 和皮肤，你会验不了。
- 之后所有命令都在你自己的 worktree 里跑，`git push -u origin feat/dp099-desktop-skeleton`。
- **不许动主目录 `depressionplex/` 里的任何文件**，不许在那里 checkout/commit。
- 干完不用删 worktree，我来收。

## 附：跑测试的注意事项（本仓踩过的坑）

- `python3 run_tests.py` 满跑 **3–4 分钟**，而单条命令 120 秒就超时。
  **要么后台跑再读输出文件，要么单独一条命令跑**；
  **绝对不要把它和 `git commit` 串在同一条命令里**（串了必超时，然后你会以为提交失败）。
- 本仓**没有 pytest 可用**（沙箱 site-packages 有 I/O 故障）。只用自带的 `run_tests.py`。
- 后台跑完要**主动去读输出文件**确认结果，不要停下来等通知。
