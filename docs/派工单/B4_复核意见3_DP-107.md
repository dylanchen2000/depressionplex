### 2.1 为什么这不是「构造不出来的输入，不用管」

`_build_run_json` 今天写不出 `chambers: null`。但同样地，引擎也写不出截短的 CSV 行——
第二轮你还是修了 G2，理由今天一字不改地适用：

- **run.json 是磁盘上的文件，不是函数参数。** 它会被磁盘写满截断、被人手工编辑、被旧版/新版
  工具写成另一个形状。DP-108 的 H10 已经摆着一个真实场景：`_build_run_json` 里调解析器抛异常，
  一次已算完的运行在写元数据那一步崩掉——那时盘上留下的就是个半成品。
- **裸 `TypeError` 在这一层等于崩窗口。** 页面按契约只接 `ResultsError`，接不到的异常会一路飞到
  Qt 事件循环。用户看到的是软件消失或一个英文栈，不是「这份结果读不了，原因是……」。

### 2.2 N2/N6 是 G1 那句假话的第二次出场（这条最要紧）

`chambers` 是 `[]` 或 `{}` 而 CSV 里**有**产出行——这在物理上讲不通：引擎不可能在计划里没有 ch1
的情况下算出 ch1 的秒数。所以这时候正确的结论是「**名册不可信**」，
而现在这一层说的是「**这些隔间不在名册里**」。

G1 那一轮我给出的裁决原文是：**名册要有「空」与「不知道」两个状态，「名册外的隔间」这个判断
只在名册可信时才允许做。** 你已经把 `chamber_roster` 做成了 `set[int] | None`——三态的位置有了，
只是「不可信」这一路没接上。这次要接上的判据：

- `chambers` 不是 list ⇒ 名册 `None` + 一条 `[上下文缺失]` 报警行说明 run.json 名册不可读；
- 任一条目不是 dict、或 `index` 不是 `int`（**`bool` 不算 `int`**，`True` 会当成 1）⇒ 同上；
- `chambers == []` 而 CSV 有产出行 ⇒ 同上（**不许**由此推出「这些隔间在名册外」）；
- `chambers == []` 而 CSV 也没有产出行 ⇒ 这才是真的「空」，照旧。

**仓里的那句规矩再补半句**：原句「未知不许长成数字的样子」，G1 加了「未知不许长成一句确定的判断」，
这一条加的是——**坏掉的名册不许长成一份空名册**。空名册是个结论，坏名册是没有结论。

### 2.3 N11 是唯一一条会印到客户纸面上的

`ResultsTable` 的字段签名写着 `scoring_window_s: list[float] | None`、`theta_mob: float | None`，
但实际存的是 JSON 里的原值，一个都没校验。我实测灌了一份坏 run.json 进去：

```
scoring_window_s = 1
theta_mob        = '很大'
video_name       = 123
video_fps        = 'abc'
video_n_frames   = []
```

这五个值**全部通过 B6 进报告的运行上下文表**（DP-110 §2 三张表之一），也就是会印在客户手里
那份 PDF 上。其中 `theta_mob` 最不能出事：**0.0175 是冻结参数，它是科学结论的一部分**，
报告上印一个 `很大` 或者印一个来自坏文件的别的数字，比读不出来严重得多。

签名写了类型而值不是那个类型，本仓有个说法：**注解不是校验，写了类型就得当真**。
要求：这几个上下文字段读进来时逐个校验类型，**不合就当「未知」（`None`）并挂一条说明**，
不许照原样往下传。`None` 到 B6 那边会被印成「未知」（DP-110 §2 已经要求解码器未知印「未知」
不许留空），这条路是通的。

### 2.4 N13：顶层不是对象时，报错要说对是哪种毛病

`run.json` 顶层是 `[]` 时说「缺少必写键 `schema_version`」——话不假，但会把人引到「谁把这个键
删了」上去查，而真相是「这个文件不是我们的 run.json」。加一句顶层类型判断即可。
