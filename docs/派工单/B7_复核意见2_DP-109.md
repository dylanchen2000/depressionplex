## §1 必须改

### A1（最重）为了绕开守卫，引擎的表达式被改了形状

`depressionplex/assay_core/segment.py` 里三处与本次任务**无关**的表达式被改写：

| 原 | 改后 | 数值 |
|---|---|---|
| `(edges[:-1] + edges[1:]) / 2.0` | `/ 2` | 完全相同 |
| `int(round(2.0 * bl))` | `int(round(2 * bl))` | 完全相同 |
| `int(round(0.02 * bl * bl))` | `int(round(bl * bl / 50))` | **不同** |

前两处数值等价，但没有任何理由——PR 正文、commit message、ISSUES 行里都没提。第三处**改变了引擎行为**：

```
bl 取 0.01–4000.00（步长 0.01，共 40 万个值）：
  min_area 不同的 bl 个数：62
  最小的一个：bl = 35.00 ⇒ 旧 25，新 24
  （0.02*35*35 = 24.500000000000004 → round → 25；1225/50 = 24.5 精确 → round → 24，银行家舍入）
  其余：bl = 55.0 (61→60)、115.0 (265→264)、255.0 (1301→1300)…全落在 .5 分界上
```

`bl = 35 px` 在 476×268 的素材上是完全正常的体长。也就是说：**一个 24 px 的斑块，在这个 PR 之前被判为不是动物，之后被判为是动物。** 这是引擎的判定行为变化，量很小，但它进的是 G7/G8 那条链。

改它的原因不是科学，是守卫：`test_single_gate_source_ast` 禁止 `100.0` / `2.0` / `0.02` 这三个 float 常量出现在**整个** `segment.py`（500 行）的任何位置，白名单只按 id 放行三个 `GATE_*` 定义。于是 `2.0`（一个和门槛无关的 `/2.0`）也被禁掉了，写代码的人就把表达式改成守卫看不见的形状。

这不是推测，变异 M11 直接证明了因果：把 `int(round(2 * bl))` 写回 `int(round(2.0 * bl))`——**数值完全不变**——`test_single_gate_source_ast` 立刻红。守卫只认字面量的类型和值，不认它是不是门槛，所以「让守卫闭嘴」的唯一办法就是把 `2.0` 变成别的形状。

反过来，`0.02 * bl * bl` → `bl * bl / 50` 这处**没有**被任何守卫拦下（`test_min_area_scales_with_bl` 确实存在，但它测的是「min_area 随 bl 单调增长」这个量级关系，看不见 .5 分界上的舍入翻转；变异 M7 把系数改成 `/49` 它是会红的）。也就是说：**守卫拦住了不改行为的那一处，放过了真改行为的那一处。**

**这正是上一轮我在 B7 复核意见里点名过的 M5 旁路**（把常量拆成 BinOp 让 float 黑名单看不见）。这一轮它没被用来绕过门槛，而是**被用来绕过守卫本身**——比绕门槛更坏，因为它把「守卫误报」的成本转嫁成了「引擎数值变化」。

**裁决（两件都要做）：**

1. **三处表达式全部还原**成 merge base 的写法（`/ 2.0`、`2.0 * bl`、`0.02 * bl * bl`）。引擎不许为了让测试闭嘴而改形状。
2. **守卫收窄作用域**，不是收窄禁令：`test_single_gate_source_ast` 只在**判定路径**上禁字面量，具体是
   - `segment.contrast_report()` 函数体内、
   - `acq_check.py` 全文、
   - `probe_frames.py` 全文、
   - `desktop/app/pages/self_test.py` 与 `desktop/app/models/self_test.py` 全文；

   `segment.py` 的其余部分不在禁令范围内。实现上用 `ast.walk` 找到 `FunctionDef` 名为 `contrast_report` 的那个子树再扫，而不是扫整个模块。
   守卫的作用域写错了就去改守卫的作用域——**不许把代码改成守卫看不见的形状。**

> 记一句给后面所有人看：**一条会误报的守卫，最后一定会被人绕过去；而绕它的那一下，往往比它防的那件事更危险。**

### A2（最重）结论区「永不为空」被做成了「永不为空，但可以是一句假话」

`desktop/app/models/self_test.py::conclusion_lines()` 最后是：

```python
if not lines:
    lines.append("全部指标通过，可以开始正式分析。")
```

把 `contrast_passed × area_jitter_passed × area_jitter_moving` 三态全枚举（27 种），实测：

```
说「全部指标通过」但其实有门没定的组合数：7
  cp=True  ap=True  mv=None
  cp=True  ap=None  mv=False
  cp=True  ap=None  mv=None
  cp=None  ap=True  mv=False
  cp=None  ap=True  mv=None
  cp=None  ap=None  mv=False
  cp=None  ap=None  mv=None
```

`cp=None` 那四行尤其严重：**对比度门没测出来，屏幕上写「全部指标通过，可以开始正式分析」。** 上一轮 H2 的毛病是「有组合什么都不说」，这一轮改成了「不知道的时候说一句肯定句」——**从沉默变成了假话，是退步不是进步。**

守卫为什么没拦住：`test_conclusion_lines_never_empty` 只断言 `len(lines) >= 1`。变异 M5（把 `if r.contrast_passed is False:` 整块删掉）跑下来 **16 条守卫全绿**——删掉一整条真实报警，没有任何一条测试变红，因为删掉之后正好落进兜底那句「全部指标通过」。

**裁决：**

1. 兜底那句改成**只有三门都是明确通过时才许出现**：
   ```python
   all_known_pass = (
       r.contrast_passed is True
       and r.area_jitter_passed is True
       and r.area_jitter_moving is not True
   )
   if all_known_pass:
       lines.append("全部指标通过，可以开始正式分析。")
   ```
2. 任何一门是 `None` 时必须有一句**明确说「这门没量出来」**的话（对比度 `None` 已被开头的 `contrast_value is None` 分支接住，但 `contrast_value` 有值而 `contrast_passed is None` 的情况没人接）。
3. 守卫从「非空」升级成「口径正确」：对 27 种组合逐一断言
   - 出现「全部指标通过」 ⟺ 三门都明确通过；
   - 每个 `False` 的门至少有一条对应的话；
   - 每个 `None` 的门至少有一条含「无法测量 / 量不了 / 没量出来」的话。

   改完必须自己拿 M5（删掉任一条 `lines.append`）打一遍，证明它现在会红。

### A4 产品运行期从 `tests/fixtures/` 读参考值，缺失时静默变横杠

```python
# depressionplex/cli/acq_check.py::_load_reference
ref_path = Path(__file__).resolve().parent.parent.parent / "tests" / "fixtures" / "p2_reference.json"
if not ref_path.exists():
    return None
```

两个问题：

1. **`tests/` 不是部署目录。** 冻结成 exe 之后 `tests/fixtures/` 不存在（B10 的两个 spec 里没有任何 `fixtures` 相关的 datas 条目，我查过了），所以**客户机上的参考列永远是空的**——`ref = r.reference or {}` + `_fmt(None)` ⇒ 表格第 4 列全是「— 灰阶」，而且不给任何理由。守卫 10 断言 `ref is not None`，在源码树里永远通过，在客户手里永远为假：**这条断言测的是 CI 的目录结构，不是产品的行为。**
2. **缺失是静默的。** `return None` 之后一路走到界面上变成横杠，「参考值没装进来」和「参考值就是空的」长得一模一样。

**裁决：**

1. 参考读数搬到引擎包内：新建 `depressionplex/assay_core/p2_reference.py`，把那 17 个字段写成一个模块级 `dict` 常量 `P2_REFERENCE`（含 `_note` / `decoder` 两段说明原样保留）。`acq_check` 直接 `from ..assay_core.p2_reference import P2_REFERENCE`——**冻结时随包走，不需要任何 datas 条目，也不可能缺失。**
2. `tests/fixtures/p2_reference.json` 保留，但改成**对账凭证**：新增守卫断言 JSON 与 `P2_REFERENCE` 逐字段相同。这样 `scripts/verify_p2_reference.py`（在有素材的机器上跑）仍然有一个 JSON 可读，而产品不再依赖它。
3. `reference` 为 `None` 这条路径在改完之后应当**不可能出现**；把它从 `AcqCheckResult` 的可选形状里去掉，或者保留为 `AcqCheckError`（部署损坏）而不是静默 `None`。

### A5 `ACQ_REFERENCE_KEYS` 一个读者都没有

`grep -rn "ACQ_REFERENCE_KEYS" --include=*.py` 全仓只有一处——它的定义。守卫 3 的 docstring 写「**每层** JSON 键集必须与 `ACQ_*_KEYS` 常量完全一致」，实际断言了顶层 / video / sampling / gates / contrast / noise_floor / area_jitter / chambers 八层，**`reference` 层没查**。于是这个 13 键的常量是一份没人核对的声明。

顺带一个直接后果：fixture 里实际有 `_note` / `_decoder_note` / `decoder` 三个额外键，一路原样流进 JSON、流进模型、流进界面——**和 `ACQ_REFERENCE_KEYS` 声明的 13 键不是一回事，而没有任何守卫会说话。**

**裁决：** 守卫 3 补上 `reference` 层的断言；`ACQ_REFERENCE_KEYS` 按实际形状补全（把 `_note` / `_decoder_note` / `decoder` 写进去，它们是有意保留的诚实注记，不是脏数据）。**注解不是校验**——一个常量声明了契约却没人对账，等于注释。

### A6 门槛数字被写进了显示字符串，AST 守卫看不见

`depressionplex/cli/probe_frames.py:193`：

```python
sanity.append("动物在动（RAD 残差 > 0.02），本帧段不适合用于噪声门判定")
```

判定用的是 `MOVING_RESIDUAL`（第 190 行），屏幕上印的是硬写的 `0.02`。**这正是 DP-109 派工单开头点名要消灭的 DP-054 形状**——「屏幕写着一个数、实际按另一个数判，改一边不报错」。守卫 `test_single_gate_source_ast` 抓不到它，因为 `0.02` 在这里是 `ast.Constant` 的 **str**，不是 float。

**裁决：**

1. 改成 `f"动物在动（RAD 残差 > {MOVING_RESIDUAL}），..."`。
2. 守卫补一条：在那五个文件里，任何 `ast.Constant` 的 **str** 值都不许包含 `GATE_CONTRAST_ABS` / `GATE_CONTRAST_RATIO` / `GATE_AREA_JITTER_P90` / `MOVING_RESIDUAL` 的十进制写法（用 `str(v)`、`f"{v}"`、`f"{v:.0f}"`、`f"{v:.1f}"`、`f"{v:.4f}"` 五种渲染逐一查子串）。**一个只查数字类型的黑名单，挡不住把数字写成字符串的人。**

### A7 守卫 11 禁的三个模式里，最常见的那种写法它抓不到

```python
FORBIDDEN = ("sys.frozen", "_MEIPASS", '__import__("sys")')
```

docstring 自己举的变异例子是「在 `engine.py` 里加回 `is_frozen = getattr(sys, "frozen", ...)` ⇒ 本条必须红」。实测这句话不成立：

```
s = 'is_frozen = bool(getattr(sys, "frozen", False))'
'sys.frozen'      in s → False
'_MEIPASS'        in s → False
'__import__("sys")' in s → False
```

`sys.frozen` 这种写法在 Python 里几乎不会有人写（未冻结时该属性不存在，直接取会 AttributeError），真实写法就是 `getattr(sys, "frozen", False)`。所以三个模式里只有 `_MEIPASS` 有牙——merge base 那两行恰好是 `getattr(sys,"frozen",False) and hasattr(sys,"_MEIPASS")`，带着 `_MEIPASS` 才被抓住；**只写前半句的最简写法，守卫全程失明。**

**裁决：** 改成 AST + 字符串常量双查：`desktop/` 里除 `utils/paths.py` 外，
- 不许出现值为 `"frozen"` 或 `"_MEIPASS"` 的字符串常量；
- 不许有 `sys` 的属性访问名为 `frozen` / `_MEIPASS`；
- 不许有 `__import__` 调用。

改完拿 `is_frozen = bool(getattr(sys, "frozen", False))` 单独打一遍变异，证明它红。

### A8 守卫 13（H5）只查一个方向

`test_desktop_model_keys_mirror_engine_keys` 的做法是：用 `ACQ_*_KEYS` 造一份最小合法 JSON 喂给 `AcqCheckResult`，不抛异常就算过。这只能查出「模型要的键比引擎给的多」（含改名）。查不出：

- **引擎加键**：模型不要求它 ⇒ 绿。变异 M4（`ACQ_JSON_KEYS` 加一个 `"extra"`）确实红了，但红的是**守卫 3**（`test_json_key_set_is_fixed`，因为 `_build_output` 没输出这个键），守卫 13 全程绿。也就是说：如果 `_build_output` 和 `ACQ_*_KEYS` 一起加了键而模型没跟上，**没有任何守卫会说话**。
- **模型少要键**：见 §5 M12。

根因是两边各写一份字面量元组（外壳不许 import 引擎，架构 §3.4，这个约束是对的），而**两份字面量之间没有对账**。

**裁决：** 模型侧的键集抽成模块级常量（`_MODEL_TOP_KEYS` 等），守卫改成**双向集合相等**断言：把引擎的 `ACQ_*_KEYS` 与模型的 `_MODEL_*_KEYS` 逐层 `==` 比较（测试文件可以同时 import 两边，产品代码不行）。**一面只照一个方向的镜子，不是镜子。**

### A9（最重）四个门槛的**数值本身**一个守卫都没有

变异结果，四条平行的实验：

| 改了什么 | 红了几条 |
|---|---|
| `GATE_CONTRAST_ABS` 100.0 → **10.0**（放松 10×） | **0** |
| `GATE_AREA_JITTER_P90` 0.02 → **0.2**（放松 10×） | **0** |
| `MOVING_RESIDUAL` 0.02 → **0.2**（放松 10×） | **0** |
| `min_area` 系数 /50 → /49 | 1 |

**把「客户这套采集条件能不能用」的门槛放松十倍，422 条测试没有一条会说话。**

三条「门常量确实被读到」的守卫（M1/M2/M3 全红）证明的是**这个常量被读了**，不是**这个常量的值是对的**。整个 PR 里，门槛的数值只以两种形式存在：`segment.py` 的定义行，和 `docs/ISSUES.md` DP-109 行里的散文（「对比度门槛…≥100」）。两者之间没有对账。

而这件事的形状和 fixture↔ISSUES.md 那条守卫（守卫 8）**一模一样**——B7 已经知道怎么做了，只是没想到门槛本身也需要：`p2_reference.json` 里的参考读数改了会红，判定门槛改了不会。**冻结了「已知良品的读数」，没冻结「判它及格的那条线」。**

**裁决：** 新增一条守卫，把 `GATE_CONTRAST_ABS` / `GATE_CONTRAST_RATIO` / `GATE_AREA_JITTER_P90` / `MOVING_RESIDUAL` 四个数值与 `docs/ISSUES.md` 里的台账文字逐字对账（与守卫 8 同形状）。门槛是产品对客户说的话，改它是科学决定，必须留痕。改完拿上面四处变异各打一遍，四处都要红。

### A10 守卫 8 把「键没了」当成了「这一项不要求出现」

```python
for key in numeric_keys:
    val = ref.get(key)
    if val is None:
        continue          # ← 这里
    if str(val) not in issues_text:
        missing.append(...)
```

变异：把 fixture 里的 `"contrast_abs"` 改名成 `"contrast_abs_x"`。守卫 8 全程绿——`ref.get("contrast_abs")` 返回 `None` ⇒ `continue` ⇒ 这一项被自己豁免了。（红的是守卫 10 的端到端断言 `"contrast_abs" in ref`，属于误伤式命中：它红的原因是模型读不到这个键，不是台账对不上。）

守卫 8 的注释写的是「防的是：fixture 里某个数字被**悄悄改掉**而 ISSUES.md 台账里没有任何记录」。改值它抓得到，**删键 / 改名它抓不到**——而删键是更彻底的一种「悄悄改掉」。

**裁决：** 四个数值键先断言**必须存在**（`assert key in ref`），再查 ISSUES.md 子串。`if val is None: continue` 这条豁免只留给**声明为可空**的字段（`sha256`、`decoder.ffmpeg_version`），并且要在断言消息里写清楚为什么允许它为空。**坏掉的名册不许长成一份空名册。**
