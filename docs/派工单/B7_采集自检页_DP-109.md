## 0. 架构师先裁的四件事（不许自行改动，改了要退回）

### 0.1 计算全在引擎侧，新开 `depressionplex/cli/acq_check.py`

三个读数的数学**已经有了**，都在 `depressionplex/assay_core/segment.py`：
`contrast_report()`、`structural_noise_floor()`、`find_chambers()`，加 `rad.trial_body_length/decompose`。
**一行都不许重写**，acq_check 只做「抽帧 → 调它们 → 序列化」。

为什么不扩 `cli/probe_frames.py`：那是给人读的排障工具（prose 输出、吃 PNG 列表），
给它再挂一份机器契约 = 一个模块两种输出契约，将来必有一边失修。
**新 CLI 的输出契约**（照 `cli/analyze.py` 的形状，§3.5）：

| 通道 | 内容 |
|---|---|
| stdout | **一个** JSON 对象，键集固定（见 §0.2 第 3 条）。这是唯一的数字出口 |
| stderr | 进度 NDJSON（照 `analyze` 现成的 `_progress` 路子） |
| 退出码 | **0 = 测到了读数（通过与不通过都算测到）**；**2 = 测不出**（无面板带 / 可用帧不足）；**1 = 解码失败** |

**退出码这条是本单最容易做错的地方**：门不通过是**一个结果**，不是一次故障。
若把「不通过」映射成非零码，GUI 会显示成「自检程序崩了」，客户永远看不到
「你的对比度只有 40 灰阶，请加背光板」这句真正有用的话。

### 0.2 门槛只许有一个来源，而且必须随读数一起过进程边界

**现在有两份，这是本单要修的第一个缺陷**：

| 出处 | 内容 |
|---|---|
| `assay_core/segment.py::contrast_report()` | `passes_gate` 里**内联字面量** `100.0` 与 `2.0`（真正做判定的那一份） |
| `cli/probe_frames.py` 顶部 | `CONTRAST_ABS_GATE = 100.0` / `CONTRAST_RATIO_GATE = 2.0` / `AREA_JITTER_GATE = 0.02`（**打印给人看**的那一份） |

判定用一份、显示用另一份 ⇒ 谁改了一边，屏幕上写着「门槛 ≥100」而实际按 150 判，**不报错**。
这是 DP-054 的形状。改法：

1. `assay_core/segment.py` 里加三个**唯一**常量
   `GATE_CONTRAST_ABS = 100.0` / `GATE_CONTRAST_RATIO = 2.0` / `GATE_AREA_JITTER_P90 = 0.02`，
   `contrast_report()` 用它们（不许再写字面量）。
2. `cli/probe_frames.py` 删掉自己那三个，改成 import。
   **注意它里面还有一个 `moving = mean(res) > 0.02`**：那是 RAD 残差的判据，
   **和面积抖动门槛数值撞巧一样**，不是同一个量 —— 给它单独起名
   （`MOVING_RESIDUAL = 0.02`，注释写明「与 `GATE_AREA_JITTER_P90` 无关，别合并」）。
3. JSON 里每个门都要带**三件**：读数、门槛、判定。GUI 只显示 JSON 说的，
   **页面代码里不许出现 100 / 2 / 0.02 这三个字面量**（守卫 §3.1）。

### 0.3 抽哪些帧是读数的一部分，必须写进 JSON

面积抖动是**相邻帧**的差，所以必须是连续帧；而全片只取一处，取到挣扎期就量到信号不是噪声
（2026-08-24 就是这么踩的：t≈24 s 那 8 帧，2/4 隔间判错，见 SPEC §1.2）。

定死一条抽帧规则，写成 acq_check 顶部的常量，**不给命令行开关**（开关一给，
两次自检就不可比）：**从全片均匀取 `N_WINDOWS = 5` 个窗口，每窗 `FRAMES_PER_WINDOW = 8` 连续帧**，
窗口中心落在 `(i + 0.5) / N_WINDOWS` 处（i = 0..4），首尾各留出 8 帧余量。
JSON 里必须有 `sampling` 块：`n_windows` / `frames_per_window` / **实际用到的帧号列表**。
理由一句话：**一个读数必须能被复现，抽了哪些帧就是它的一部分。**

面积抖动 p90 的**判定隔间**照 P2 的 B2 判据来：取 RAD 残差最低的那个隔间
（`SPEC_胶带走廊标定_v1.md` §5 的 B2：「B 批中 RAD 残差最低的隔间，面积抖动 p90 ≤ 0.02」）。
其余隔间的读数照样进 JSON（诊断量），但**不参与判定**，且 JSON 里要标明哪个隔间被选中、残差多少。
动物在动时的抖动是信号 —— 这一点必须在页面上用人话写出来，否则客户会以为门坏了。

### 0.4 参考素材的四个读数只能当参考，不许冒充本机结果

档案里的 P2 读数（`docs/STATUS.md`「P2 硬门实测结果」）：
**对比度 208.5 灰阶 / 6.77×、结构噪声底 0.43 px、静止隔间面积抖动 p90 = 0.0035**，
素材是 `10mg 2周.mp4`（476×268 / 25 fps / 9661 帧）的第 600–607 帧。

**那段素材不在仓里，也不许进仓（大文件规矩），沙箱和 CI 都没有它。**
所以：

- 四个数字冻结成 `tests/fixtures/p2_reference.json`，连同素材标识
  （文件名、分辨率、帧率、总帧数、帧号区间）与容差。**素材的 SHA256 我们现在不知道 ⇒ 写 `null`，不许编一个。**
- 写 `scripts/verify_p2_reference.py`：在**有那段素材的机器上**跑 acq_check 并与冻结表比对，
  不符即非零退出。沙箱与 CI 跑不了它 —— **交付报告里必须写「参考读数未在本环境复现（没有素材）」，
  不许写成「应该能复现」**（本项目铁律：查不到 ≠ 没有）。这一条我（架构师）拿到素材后自己跑。
- 页面上参考值那一列的表头必须是**「参考素材（2026-08-24 实测）」**，
  和「本机实测」并排且不许混排。参考值**只能从 `p2_reference.json` 读**，不许写死在页面代码里。

## 1. 要做什么

| 文件 | 内容 |
|---|---|
| `depressionplex/cli/acq_check.py` | 新引擎 CLI。`--video PATH --chambers N --json`；输出见 §0.1/§0.2/§0.3。**只调 assay_core，不重算数学** |
| `depressionplex/assay_core/segment.py` | 加 §0.2 的三个门槛常量，`contrast_report` 改用它们（**判定逻辑与数值一个都不许变**） |
| `depressionplex/cli/probe_frames.py` | 删掉三个重复常量改 import；`moving` 的 0.02 单独起名 |
| `desktop/app/services/engine.py` | 加 `acq_check_argv(video, n_chambers)`（argv 只有一处拼装，和 `build_argv` 做邻居）。**引擎路径一律走现成的 `engine_command()`；若 B10 已合入 main，用它改后的版本，不许自己再拼一次路径** |
| `desktop/app/models/self_test.py` | **纯标准库**读 JSON。键集缺一即抛（不许 `.get(键, 默认值)`）；读不到的读数是 `None`，**不是 0** |
| `desktop/app/pages/self_test.py` | Qt 页面。类名 `AcqCheckPage`。三行门 + 诊断表 + 参考列 + 一段人话结论 |
| `desktop/app/main_window.py` | 挂上这一页（替掉占位） |
| `tests/test_acq_check.py` | 见 §3，记进 `run_tests.py` 的 `TEST_MODULES` |
| `tests/fixtures/p2_reference.json` + `scripts/verify_p2_reference.py` | 见 §0.4 |

**命名禁令**：`python -m desktop.main --self-test` 这个旗标**已经存在**，意思是
「把所有页面构造一遍就退出」（CI 的 Desktop Self-Test 在用）。本页是**采集自检**，
两回事。不许复用那个旗标名、不许把新页面挂到那个旗标上、不许改它的行为。
页面对用户显示的名字用**「采集自检」**。

页面上必须有的人话（文案照抄，这几句是我写的，不许改意思）：

- 对比度不达标 ⇒ 「**背光不足或曝光不当**。我们的分割靠亮背板 + 黑剪影，
  绝对差 < 100 灰阶时阈值分割会不稳。建议加背光板或调曝光后重录一段再自检。」
- 抽样窗口里动物一直在动 ⇒ 「**本次抽到的帧里动物都在动，抖动读数含真实形变，
  不能当噪声底看。** 换一段有静止时段的素材再自检。」
- 测不出（无面板带）⇒ 「**没找到背光面板行带**，说明画面结构与我们假设的不同
  （亮背板横贯全宽、动物在其下方）。这不是「不达标」，是「量不了」——请把一帧截图发给我们。」

## 3. 测试（`tests/test_acq_check.py`，每条都要能被变异打红）

1. **门槛只有一个来源**：AST 守卫 —— `cli/acq_check.py`、`cli/probe_frames.py`、
   `desktop/app/pages/self_test.py`、`desktop/app/models/self_test.py` 里
   **不许出现常量 `100.0`/`100`、`2.0`、`0.02`**（查 `ast.Constant` 的数值，跳过 docstring 节点）；
   必须以 `ast.Load` 的方式用到 `GATE_CONTRAST_ABS` / `GATE_CONTRAST_RATIO` / `GATE_AREA_JITTER_P90`
   （**查 `ast.Load` 不查字符串** —— 「出现过这个名字」不等于「用了这个值」，这是本仓成文的教训）。
2. **判定真的读那三个常量**：把 `segment.GATE_CONTRAST_ABS` 临时改成 `1e9`，
   对一张合成高对比图断言 `passes_gate` 变假；改回。（变异：`contrast_report` 里写回字面量 ⇒ 这条必须红。）
3. **JSON 键集固定**：`acq_check.ACQ_JSON_KEYS` 一份清单，断言输出键**逐个相同**（缺、多都红）；
   嵌套块（`gates` / `sampling` / `chambers[]` / `reference`）各自也有清单。
4. **门不通过 ⇒ 退出码 0**：合成一段低对比素材，断言 rc == 0 且 `gates.contrast.passed is False`。
5. **测不出 ⇒ 退出码 2，且读数是 `null` 不是 0**：合成一张没有面板带的图，
   断言 rc == 2、`gates.contrast.value is None`。**这条是「未知不许长成数字的样子」**。
6. **同一素材两次跑，JSON 逐位相同**（除 `generated_at` 一个键 —— 时间戳必须**单独一个键**，
   不许嵌进别的字符串里）；断言 `sampling.frame_indices` 出现在输出里且两次相同。
7. **判定隔间选的是残差最低那个**：造三个隔间、残差人为拉开，断言 `gates.area_jitter.chamber`
   等于残差最低的那个，且另两个隔间的读数仍在 `chambers[]` 里（诊断量不许被丢）。
8. **冻结表与文档一致**：从 `docs/STATUS.md` 用正则抓 208.5 / 6.77 / 0.43 / 0.0035，
   断言与 `tests/fixtures/p2_reference.json` 相同。（防的是文档改了参考值而 fixture 没跟 —— 两处各写一遍必然分叉。）
9. **页面不许自己算**：`pages/self_test.py` 与 `models/self_test.py` 不许 import
   `numpy` / `statistics` / `math`，也不许 import `depressionplex`（把 DP-100 的
   `test_no_pyside_and_no_engine_import` 扩到这两个新文件）。
10. **端到端**：真跑一次 `cli.acq_check.main([...])` 产出 JSON，**用它**喂 `models/self_test.py`，
    断言三行门都读得出、参考列读得出、诊断表行数 == 隔间数。**不许拿手写的假 JSON 当唯一夹具**（DP-102 就是这么绿着交出错数字的）。

## 4. 怎么验收（缺一条即退回）

1. `python3 run_tests.py` 全绿（后台跑，约 4–5 分钟），总数 = 你开工时 `main` 上的基线 + 新增条数，账要对得上。
2. **变异检验自己做**：`/tmp/mutate_b7.py`，每条守卫至少一个变异（把门槛字面量写回 `contrast_report`、
   把「不通过」改成 rc=2、把测不出的读数兜底成 0、把诊断隔间过滤掉、把参考值写死进页面…），
   逐条报吃劲/装饰，**装饰的改到吃劲**。**脚本先跑基线，基线必须全绿**再开始量。
3. `Tests` + `Desktop Self-Test` 双绿。
4. 交付报告回答 `_共同约定_v1.md` §5 每一条，另加三条：
   - §0.4 的参考读数**在本环境未复现**（没有素材）—— 明写，不许含糊；
   - 你抽帧规则的实现里，若素材短于 `5×8 + 余量` 帧会怎样（要有明确行为，不许悄悄少抽）；
   - `contrast_report` 你**改了什么、没改什么** —— 判定数值必须逐位不变，说明你怎么验的。
