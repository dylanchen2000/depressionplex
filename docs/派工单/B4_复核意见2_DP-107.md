## 二、必须修的 4 条（都是我探针里当场跑出来的）

四条同一个病根：**CSV / run.json 长得不对时，这一层有时候崩、有时候悄悄丢数据、有时候印出假话。**
F6 只把「坏 `trial_id`」这一种堵上了，旁边还开着三扇门。

### G1（最重）run.json 缺失时，所有 scored 行被改成 alarm，且 reason 是**假话**

实测（CSV 有 ch1/ch3 两行，都 `scored=True`；run.json 不存在）：

```
行数=3
ch=None kind=alarm  reason='上下文缺失：run.json 文件不存在…'      ← 这行是对的
ch=1    kind=alarm  immob='200.0' reason='CSV 里出现了名册外的隔间（run.json chambers[] 里没有 ch1）'
ch=3    kind=alarm  immob='200.0' reason='CSV 里出现了名册外的隔间（run.json chambers[] 里没有 ch3）'
```

两处错：

1. **违反派工单 §2.1 第 1 条**：「CSV 在、run.json 不在 ⇒ **可以显示数字**，
   但必须把「上下文缺失」作为一条报警行显示」。现在数字虽然还在字段里，
   但整表被标成 alarm —— 页面会给每一行都上报警底色，**用户看到的是「这次运行全体异常」**，
   而事实是数字都在、只是上下文文件丢了。
2. **reason 在陈述一件假事**：「run.json chambers[] 里没有 ch1」——
   run.json **根本不存在**，它的 `chambers[]` 里既没有也不可能有任何东西。
   本仓的规矩是「未知不许长成数字的样子」，这条是它的孪生：**未知不许长成一句确定的判断。**
   更要紧的是 **B6 会把 `reason` 原文印进客户的 PDF 报告**（DP-110 §0.4），
   这句假话会落在纸上。

要求：`chamber_roster` 有「空」和「不知道」两种状态，**必须分开**。
run.json 不存在 ⇒ 名册**未知** ⇒ ①CSV 行保持它自己的 `kind`（`scored` 列说 True 就是 scored），
②不许给任何行挂「名册外」这种 reason，③那条 `chamber=None` 的上下文缺失报警照旧留着。
「名册外的隔间」这个判断**只在 run.json 存在时才允许做**。

### G2 CSV 行被截短 ⇒ `AttributeError`，不是 `ResultsError`

实测（表头合法，数据行只有前 3 个值）：

```
AttributeError: 'NoneType' object has no attribute 'lower'
```

`csv.DictReader` 对缺失的尾部列填 `None`（`restval`），于是 `scored` 是 `None`，
`None.lower()` 当场炸。页面只会接 `ResultsError`（B4 §2.1），
这个异常会**穿透到 Qt 事件循环**，客户看到的是崩溃或一个没有任何解释的报错框。

### G3 CSV 行比表头**多**一个值 ⇒ 多出来的值被静默丢掉

实测（表头 16 列合法，数据行 17 个值）：不报错，第 17 个值消失（`DictReader` 的 `restkey` 落在 `None` 键里，没人看）。

G2 与 G3 是同一枚硬币：**行的长度不等于 16 时，一边崩、一边悄悄丢。**
一起修：读每一行时断言「这一行恰好 16 个值」——
`None` 不在 `row_dict` 的键里（没有多出来的值）**且**没有任何字段的值是 `None`（没有缺的值），
否则 `ResultsError`，报错里带行号、实际列数、期望列数。
**注意别用「值是空串」来判缺失** —— 空串是引擎的合法输出（未放行 ⇒ 留空），
`None` 才是「这一行根本没这么多列」。这两者混掉就把 F3 的行判成坏行。

### G4 CSV 里同一个隔间出现两行 ⇒ 前一行被静默覆盖

实测（ch1 两行，第二行 `immobility_s=9.9`）：表里只剩一行，显示 `9.9`，**第一行连声响都没有**。

根因是 `csv_rows[chamber] = row_dict` 直接赋值。这就是 F6 那句「能被跳过的数据等于没有」，
只是换了个位置：**一只动物的数字被另一行悄悄顶掉，用户不可能发现。**
要求：`chamber` 已在 `csv_rows` 里 ⇒ `ResultsError`，报错里带两行的行号与 `trial_id`。

### G5（顺手，一行）`scored` 列不是 `True`/`False` 时被当成 False，还配一句假话

实测 `scored="yes"` ⇒ `kind='alarm'`、`reason='CSV 标了未放行计分，但引擎没给原因'`。
引擎写这一列的是 Python `bool`（`cli/analyze.py:74` ⇒ csv 写出 `True`/`False`），
**没有第三种合法取值**。`"yes"` 只能来自文件被改过或格式变了 —— 那是 F6 同一类事，要停。
要求：`{"true","false"}` 之外（大小写不敏感、去空白后）一律 `ResultsError`。
**不许保留现在这个「认不出就当没放行」的兜底** —— 它会给一行真数字配上「未放行」的标签。

### G6（可选，你自己判断值不值）名册里的 `index` 不做合法性检查

实测名册 `(0, 1)` ⇒ 表里出现 `ch0`。引擎的隔间号是 1 起（`runner.py:284`），
`0` 或负数只能是坏文件。你的 F7 守卫查的是「所有行的 chamber 是 None 或 ≥1」，
但那只覆盖你自己造的夹具，坏名册能绕过去。加一句检查很便宜；
**若你认为这属于过度防御，就在交付报告里写一句理由，我不强求。**
