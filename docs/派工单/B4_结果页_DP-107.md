里程碑：本单交付后 **M1 完成**（B3a + B2 + B3 + B4），M2 研究版才有东西可发（道俊 2026-09-13 已批「可以发」）。

## 1. 背景：这一页最容易做错的一件事

结果页看起来是「把 CSV 显示出来」，但本仓最贵的几个缺陷全长在这一层：

- **DP-054**：同一个数字有两条来路，其中一条变了没人发现。
- **DP-102 复核查出的四个缺陷，根因只有一个**：键名与文件名各有多份派生器，
  而消费方的测试喂的是自己造的夹具 —— 于是「测试全绿 + 用户拿到的数字是错的」同时成立。

所以本单的判据不是「表格能显示」，而是**这一页里不许出现任何新的数字来源**：

| 要显示的东西 | 唯一来源 | 不许 |
|---|---|---|
| 所有秒数、帧数、占比、`validity_status`、`scored` | `<stem>.csv` 的 16 个字段 | 不许在外壳里算、不许四舍五入后再当数用 |
| 未产出数字的隔间、原因、隔间几何、`plan_warnings`、θ_mob、计分窗口、`tool_version` | `<stem>_run.json` | 不许拿 CSV 里的值反推 |
| 四个产出文件的文件名 | `services/engine.output_paths()` | **不许再拼一次文件名**（第四个派生器） |
| 发布态徽章（黄/绿） | `services/calibration.py` | 不许自己判、不许硬写「研究版」字样 |

**一句话**：本页只做「读 + 摆」，一个 `+`、一个 `/`、一个 `round()` 都不许出现在数字上。
需要合计/均值请**退回给我**（架构师），那是 B6 报告的事，且必须由引擎侧算。

## 2. 要做什么

### 2.1 纯模型层：`desktop/app/models/results.py`（**只用标准库**，不 import PySide6）

沙箱里没有能用的 PySide6，所有测试只测这一层。Qt 页面只许调用它，不许自己解析文件。

```python
CSV_FIELDS_EXPECTED: tuple[str, ...] = (...)   # 16 个，按引擎的顺序抄一遍
```

**为什么是「抄一遍」而不是 `from depressionplex.cli.analyze import CSV_FIELDS`**：
架构 §3.4 规定外壳不许 import 引擎包（B10 的 GUI spec 写 `excludes=["depressionplex"]`，
DP-100 有 `test_no_pyside_and_no_engine_import` 守着）。所以契约靠**测试**钉住：
测试层两边都能 import，写一条断言 `CSV_FIELDS_EXPECTED == analyze.CSV_FIELDS`（**顺序也要相同**）。
同型做法见 `tests/test_experiment_contract.py::test_contract_fields_match_cli_flags`。

必须提供（名字可商量，行为不可）：

1. `load_results(exp: dict, video_index: int) -> ResultsTable`
   - 文件名一律走 `engine.output_paths(exp, video_index)`。
   - CSV 表头必须**逐字段逐顺序**等于 `CSV_FIELDS_EXPECTED`，不等就抛 `ResultsError`
     并说清「多了哪些、少了哪些」。**不许 `.get(键, 默认值)`**（DP-102 的原罪）。
   - `run.json` 的 `schema_version != "1"` 一律拒（照 `engine.require_contract` 的口径）。
   - CSV 在、run.json 不在 ⇒ **可以显示数字，但必须把「上下文缺失」作为一条报警行显示**；
     反之 run.json 在、CSV 不在 ⇒ 全部隔间都是报警行（这正是退出码 2「无产出」的样子）。
2. `ResultsRow`：一行 = 一个隔间。两种行**同一个类型**，靠字段区分，不许分成两个列表：
   - `scored=True` 的行：16 个字段原样带着（字符串就是字符串，**不许在这一层转 float**）。
   - `scored=False` / 根本没有 CSV 行的隔间：`kind="alarm"`，带 `reason`（来自 run.json
     `not_scored[].reason` 或 `chamber_validity[].status/note`）。
   - **`trial_id` 只许有一个派生器**：`trial_id(stem, chamber) -> f"{stem}-ch{chamber}"`
     （与 `runner.py:284` 同一个形状），全模块只写一次，测试里对着引擎产物核。
3. `DENOMINATORS: dict[str, tuple[str, ...]]`：每个秒数列 → 它的分母列。
   至少 `immobility_s` / `immobility_raw_s` / `mobility_s` / `first_mobility_onset_s`
   要各自指到 `window_frames` / `scorable_frames` / `unknown_frames_window` / `fps` 里该指的那些。
   **哪个指哪个由你按 §3.5 与 `cli/analyze.py` 的 `_row()` 判断，判不准就在交付报告里问，不许猜。**

### 2.2 Qt 页面：`desktop/app/pages/results.py`（替换 `placeholders.ResultsPage`）

- 表格用 `QTableWidget`（不要上 `QAbstractTableModel`，这一页不值那个复杂度）。
- **每个秒数列旁边必须紧跟它的分母列**，且列头写明「(分母)」。缺一列即退收。
- **空值一律显示 `—`，并在同一行的备注列写「未放行计分」**。
  **`0` 是最危险的假信号**：`immobility_s` 填 0 会被读成「一秒都没不动」，
  而那正好是最强抑郁表型的反面（`tests/test_analyze_cli.py` 有对应守卫，别把它绕过去）。
- **报警行必须留在表里**，用行底色区分，**不许折叠、不许放到另一个 tab、不许只写一句汇总**。
  「隔间从表里消失」是本产品最不能出的一种错：用户会以为那只动物没做实验。
- 页面顶部一行元信息（全部读 run.json）：`tool_version`、`assay`、计分窗口秒数、
  `rules.theta_mob`、视频名与 fps 及其 `frame_count_source`。
- 徽章：页面右上留一个空容器 `self.badge_slot: QWidget`，**B8（我自己做）往里挂**。
  你只负责留位置，**不许自己写发布态文案**。
- 打开方式：工具栏「打开输出目录…」选一个含 `experiment.json` 的目录，
  读 `experiment.json` → 逐 `video_index` 列出 → 选一段显示。
  队列页跑完自动跳转本页这件事**不在本单范围**（要改两页的耦合，我另开一单）。

## 3. 测试（新建 `tests/test_results_model.py`，登记进 `run_tests.py` 的 `TEST_MODULES`）

`run_tests.py` 有元守卫 `test_run_tests_registry`，忘了登记会直接红。

必须有的守卫（每条都要能被变异打红，见 §4）：

1. **字段契约**：`CSV_FIELDS_EXPECTED == analyze.CSV_FIELDS`（含顺序）。
2. **表头不符即拒**：少一列、多一列、换顺序，三种各抛一次，报错里要点出差哪些。
3. **分母表覆盖全**：凡列名以 `_s` 结尾的字段，`DENOMINATORS` 里必须有条目 —— 
   用**遍历 `CSV_FIELDS_EXPECTED` 生成**的断言，不许手写一张清单
   （手写的清单在引擎加第 17 个字段时不会变红，等于装饰）。
4. **空值不许变 0**：喂一行 `immobility_s=""`，断言模型层给出的是「无」而**不是** `0`/`0.0`/`"0"`。
5. **报警行不许消失**：造一份 CSV 只有 ch1、ch3，run.json 的 `not_scored` 有 ch2、
   `chamber_validity` 有 ch4 ⇒ 表必须是 4 行，且 ch2/ch4 是 `kind="alarm"` 且带得出原因。
6. **两个文件缺任意一个的行为**（见 2.1 第 1 条），各一条。
7. **文件名不许第二次派生**：AST 守卫 —— `models/results.py` 里不许出现
   `"_run.json"` / `".csv"` / `"_timeline.csv"` / `"_report.txt"` 这些**字面量**，
   路径必须来自 `engine.output_paths`。（查 `ast.Constant` 的字符串值，不要 grep。）
8. **外壳不许 import 引擎**：照 DP-100 的 `test_no_pyside_and_no_engine_import` 加一条，
   覆盖新增的两个文件。
9. **端到端夹具**：拿 `tests/` 里现成的合成手段跑一遍 `cli/analyze.py --csv --run-json`，
   **用引擎真产出的两个文件**喂模型层，断言 4 行、分母齐、报警行在。
   **不许用手写的假 CSV 当唯一夹具** —— DP-102 就是这么绿着交出错数字的。

## 4. 怎么验收（缺一条即退回）

1. `python3 run_tests.py` 全绿，且**总数比合入前多出你新增的条数**（本单基线 406）。
2. **变异检验自己做**：写一个 `/tmp/mutate_b4.py`，对每条守卫至少造一个变异
   （删掉表头校验、把空值兜底成 0、把报警行过滤掉、把文件名字面量写回去…），
   逐条报「吃劲 / 装饰」。**装饰的守卫要改到吃劲为止**，交付报告里贴这张表。
3. Actions 双绿：`Tests` + `Desktop Self-Test`（ubuntu offscreen + windows）。
   自检要能打出结果页（`python -m desktop.main --self-test` 已有构造全部页的逻辑，别让它炸）。
4. 交付报告回答 `_共同约定_v1.md` §5 的每一条，另加两条：
   - 你给 `DENOMINATORS` 的每一条**凭什么**这么指（引 `cli/analyze.py` 的行号）；
   - 有没有哪一处你想算个数被本单挡住了 —— 说出来，那是 B6 的输入。

## 5. 本单特有的禁令

- 不许在外壳里**重算**任何科学量（含合计、均值、单位换算、四舍五入后再参与比较）。
- 不许把 `validity_status` 或 `scored` 翻译成新的词汇表（例如把 `unknown` 显示成「正常」）。
  要加人话解释就**并排显示**原值与解释，原值必须在。
- 不许因为「没内容」就不显示某个键。键不许消失（共同约定 §1）。
- 不许在本页做任何写盘动作（导出是 B6）。
- 不许改引擎侧任何文件。发现引擎缺东西 ⇒ 写进交付报告，我来改。
