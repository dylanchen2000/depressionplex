# 派工单 B12：配套 CSV 交叉核对改成「逐份导出对账」（DP-127）

**先读 `docs/派工单/_共同约定_v1.md`**，尤其 §3 通用禁令、§4 测试纪律、§6 复核累积铁律。
本单只做一件事：**把 `crosscheck_summary_csv` 的对账粒度从「全目录对全目录」改成「逐份导出对逐份 CSV」**。

## 0. 架构师已裁的四条（不许自行改动，改了退回）

这四条是口径，不是实现偏好。**你的活是照做 + 配守卫，不是重新判一遍。**

### 0.1 对账单位是**一次会话**，不是一个目录

一份 `human_scores_*.csv` 是某一次会话导出的快照，它只该跟**同一次会话**导出的那份
`timer_audit_*.json` 对账。现在的代码把同一评分员的**全部**读数塞进一个
`by_trial = {r.trial_id: r for r in rows}`（`depressionplex/human_agreement.py:550`），
于是一个键有两条读数时**后者静默覆盖前者**，CSV 拿到的是哪一条全凭字典顺序。

### 0.2 配对靠数据自证，不靠文件名

**不许用文件名的日期去配对。** 2026-09-07 那天同一个人导出过两批，文件名撞在一起、
靠浏览器加的 `(1)` 才没被覆盖（DP-077 ①）。配对规则如下：

对每一份 CSV，候选是**同一评分员的全部**审计 JSON；一份 JSON 算配上，必须同时满足

1. CSV 里每个 `trial_id` 都在这份 JSON 的 `records` 里出现；
2. 每条的 `presentation_order` 与这份 JSON 里的**逐条相等**。

- **恰好一份满足** ⇒ 配对成功，逐条数值只跟这一份核。
- **零份满足** ⇒ 报「这份 CSV 配不上任何一份导出」，并把**差得最少**的那份的前
  5 条差异一起打出来。**这是真账，不许静默跳过。**
- **两份以上满足** ⇒ 报「配对不唯一」，把候选文件名全列出来。**不许挑一份。**

`presentation_order` 参与配对以后就**不再单独当一条不一致来报**——它已经是配对的判据了。
跨会话比 order 本来就没有意义（order 是会话内序号，09-07 与 09-08 两批都有 order=27）。

### 0.3 `None` 对 `None` 不是不一致

`_crosscheck_one_csv` 现在写的是
`if c_mob is None or j_mob is None or abs(c_mob - j_mob) > TOL`（`:520`），
于是**两边都是「没有」也被判成对不上账**。改成：

| CSV | JSON | 判定 |
|---|---|---|
| 有 | 有 | 差值超容差才报（容差 `SUMMARY_CSV_MOBILE_TOL_S` 不许动） |
| 无 | 无 | **一致**（两边都说「这一场没有这个数」） |
| 只有一边有 | —— | 报，并**明说是哪一边缺**（现在的文案 `CSV=None ≠ JSON=None` 说不出这件事） |

### 0.4 「JSON 有 CSV 无」仍按并集判，且**要看全部读数**

DP-076 那条不动：缺失只能对同一评分员**全部**分次导出的并集判。但并集的两边都要修：

- JSON 侧要包含**全部读数**（真值 + 已声明复评），不是只有归并后的真值表。
  现在 `build_table` 在归并**之后**才做交叉核对（`:921–931`），复评那一条已经被移出
  `result.rows`，于是每一个被声明为重评的键都被报成「读数不同」。
  改法：把 `result.rows + result.repeat_rows` 一起交给核对。
- CSV 侧仍是那位评分员的全部 `human_scores_*.csv`（不含 `SALVAGED`）。

## 4. 测试（加进 `tests/test_human_agreement.py`，不新建模块）

每条规矩要有**踩上去会红**的测试。至少这些形状：

1. 两份导出、两条不同读数、CSV 只对应其中一份 ⇒ **不报不一致**（这是现在那 38 条的最小复现）。
2. CSV 里某条 `mobile_seconds` 空、JSON 侧也空 ⇒ 不报；只有一边空 ⇒ 报，**且报文里说得出是哪边缺**（断言字符串内容，不是断言「有一条」）。
3. 同一 `trial_id` 在两份导出里 order 不同（27 与 4）⇒ 配对把它们分开，**不产生 order 不一致**。
4. 一份 CSV 配不上任何导出 ⇒ 报「配不上」+ 打出最接近那份的差异。
5. 一份 CSV 同时配上两份导出（构造两份内容一致的导出）⇒ 报「配对不唯一」并列出候选，**不许挑一份**。
6. 真数据守卫：`build_table(INCOMING)` 的 `crosscheck_mismatches`，断言**具体条数与内容**（把清单钉住），不是断言「少于 48 条」。
7. 回归：`data/human_scores/raw/` 的核对结果**逐字不变**（那 57 条没有重复键，这一单不该动它）。

**变异证明（交付报告里逐条写「改了什么 → 红了哪几条」）**，至少：

- M1 `None/None` 改回「报不一致」⇒ 测 2 红
- M2 配对退回全目录字典 ⇒ 测 1 红
- M3 「配对不唯一」改成取第一份 ⇒ 测 5 红
- M4 `build_table` 不传 `repeat_rows` ⇒ 测 1 或测 6 红
- M5 「JSON 有 CSV 无」改成逐份判 ⇒ 应该有测试红（DP-076 那条老守卫还在，别把它弄没了）
- M6 真数据那条清单断言改成「非空即可」⇒ 你自己造一条假不一致，它必须还红

**变异必须逐字节还原并 sha256 校验。一条永不还原的变异会架空它后面所有守卫。**
