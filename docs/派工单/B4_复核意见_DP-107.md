## 一、必须修的 8 条

### F1（最重）名册没有来源，隔间会静默消失

实测：run.json 的 `chambers` 有 4 个（index 1–4），CSV 只有 ch1/ch3，`not_scored` 与 `chamber_validity` 都是空 ⇒

```
行数: 2  [(1,'scored'), (3,'scored')]
```

ch2、ch4 **不在表里，也没有任何提示**。用户会以为那两只动物没做实验。

根因：现在的名册是「CSV 提到的」∪「两个报警源提到的」。**run.json 的 `chambers[].index` 是唯一权威名册，代码里一次都没读**。而那两个报警源都不保证覆盖：引擎在隔间层之前失败（分割失败、走廊标定失败到进不了 trial 循环）时，两个列表都可能是空的。

要求：名册 = run.json `chambers[].index`。名册里任何一个隔间，只要 CSV 没有它、两个报警源也没有它 ⇒ **必须补一条 `kind="alarm"` 行**，`reason` 写清「run.json 的名册里有本隔间，但产出与报警里都没有它 —— 引擎在隔间层之前就停了或产出不完整」。CSV 里出现了名册外的隔间，同样报警（不是丢掉）。

### F2 没有 CSV 时表可能是空的，且注释写着「已覆盖」

实测：CSV 不存在、run.json 在、两个报警源为空 ⇒ **行数 0**，不抛错。

这正是引擎退出码 2（一个数字都没产出）的样子，也就是用户最需要解释的一次运行，结果结果页一片空白。代码里第 275 行那句 `# 情况3：CSV 不存在但 run.json 存在 → 所有隔间都是报警行（这已经被上面的逻辑覆盖了）` **是错的**，请连注释一起改。F1 修好后这条自动成立，但**必须单独有一条守卫**，因为它是本页最贵的用户场景。

### F3 `scored=False` 的 CSV 行被当成 scored 行

实测：CSV 里一行 `scored="False"`、`gate_messages="排除态不放行计分"` ⇒ `kind='scored'`、`reason=None`。

派工单 §2.1 第 2 条写的是「`scored=False` / 根本没有 CSV 行的隔间：`kind="alarm"`」。现在 `kind` 只由「这一行来自 CSV」决定，跟 `scored` 列无关。后果：这一行不会被行底色标出来，用户看到的是一行「所有秒数都是 —」的**正常行**，而它为什么没数字（`gate_messages` 里写着）没进 `reason`。

要求：`scored` 列为假 ⇒ `kind="alarm"`，`reason` 取 `gate_messages`（空则写明「CSV 标了未放行计分，但引擎没给原因」）。**16 个字段照旧原样带着**，不许因为改成 alarm 就把字段丢了。

### F4 `trial_id` 有两个派生器，同一张表里会出现两个前缀

实测：`trial_prefix="TST-007"`、视频文件名 `IMG_0042.mp4` ⇒

```
[(1,'scored','TST-007-ch1'), (2,'alarm','IMG_0042-ch2')]
```

引擎的规则是 `runner.py:340`：`prefix = trial_prefix or Path(path).stem`。`models/results.py` 里报警行用的是 `Path(exp["videos"][i]["path"]).stem`，**把用户填的前缀丢了**。而 `trial_prefix` 是向导里的正式功能（`pages/new_experiment.py:120-124`）。这就是 DP-102 那四个缺陷的同一个形状：一个名字两份派生器，各自的测试喂各自的夹具。

要求：前缀派生**只许一份**，放进 `desktop/app/services/engine.py`（`output_paths` 的邻居，那里已经是「文件名只有一处派生」的家），例如

```python
def trial_prefix(exp: dict, video_index: int) -> str:
    """CSV 里 trial_id 的前缀。与引擎 runner.py:340 同一条规则。"""
```

注意**不要和文件名混为一谈**：产出文件名永远是 `path.stem`（`OUTPUT_SUFFIXES`），`trial_id` 前缀是 `trial_prefix or path.stem`。两件事、两个函数、各一份。守卫要**拿引擎真跑一次 `--trial-prefix` 与文件名不同的产物**来核，光对着手写夹具核不出这条。

### F5 编造出来的 `.get(键, 默认值)` —— 其中一个编出了合法取值

```python
status = cv.get("status", "unknown")          # 173 行区
rules  = run_data.get("rules", {}); rules.get("theta_mob")
reason = item.get("reason", "未产出数字")
not_scored_list      = run_data.get("not_scored", [])
chamber_validity_list = run_data.get("chamber_validity", [])
video_info = run_data.get("video", {})
```

`"unknown"` **是 `validity_status` 的一个合法取值**，所以 run.json 里少了 `status` 这个键，读出来的东西看着完全正常 —— 这是本仓最忌的失败（不报错、不告警、数字看着挺正常）。实测：`chamber_validity` 里给一条不带 `status` 的记录 ⇒ 报警行 `reason='unknown'`，无一处提示这是编的。

同理 `rules` 缺失 ⇒ `theta_mob` 静默为 `None`（实测确认），页面上就显示成「θ_mob 未知」，而真相是**这份 run.json 不是我们的引擎产的**。

要求：run.json 是**我们自己引擎的产物**，不是外来数据。凡引擎必写的键，缺了就是契约破裂 ⇒ 抛 `ResultsError`，说清缺哪个键、在哪个文件。派工单 §2.1 那句「不许 `.get(键, 默认值)`（DP-102 的原罪）」指的就是这些。可以带默认的只有一类：**引擎自己就允许为 `null` 的字段**（那时读到的是 `None`，不是编的）。B10 会往 run.json 加 `decoder` 块，「容忍未知的新键」这条现有行为对的，别动。

### F6 认不出的 CSV 行静默消失

```python
if "-ch" in trial_id_str:
    try: chamber = int(...)
    except (ValueError, IndexError): pass   # ← 整行没了
```

`trial_id` 认不出来 ⇒ 这一行连人带数字一起从表里消失，没有任何声响。实测：两行 CSV，一行 `trial_id="被改坏的名字"` ⇒ 表里 1 行，不报错。

要求：认不出就 `ResultsError`，报错里带上原始 `trial_id` 与行号。**「能被跳过的守卫等于装饰」的孪生兄弟是「能被跳过的数据等于没有」**；何况这一列是引擎写的，认不出说明文件被改过或格式变了 —— 那是必须停下来的事。

### F7 `chamber=-1` 这个哨兵值不许存在

run.json 缺失时插了一行 `chamber=-1` 的行。一张按隔间号排序、按隔间号显示的表里塞一个假隔间号，下游（B6 报告、B7 自检）只要拿 `chamber` 去拼文案，就会印出「隔间 -1」。

要求：`ResultsRow.chamber: int | None`，非隔间级的报警行用 `None`，排序时 `None` 排最前。**「未知不许长成数字的样子」**（本仓成文的规矩）。

### F8 `DENOMINATORS` 四条里有三条指错了

现在写的：

```python
"immobility_s":            ("scorable_frames",)
"immobility_raw_s":        ("scorable_frames",)
"mobility_s":              ("window_frames", "fps")
"first_mobility_onset_s":  ("fps",)
```

对着引擎的实现核（`depressionplex/assay_core/trial_report.py`）：

| 行 | 事实 |
|---|---|
| 189 | `window_s = window_frames / fps` |
| 191–192 | `mirror_pipeline = window_s - mob.seconds_pipeline`，`mirror_raw = window_s - mob.seconds_raw` |
| 253–259 | 引擎自己的报告**同时**印「占窗口」（÷`window_seconds`）与「占可评分」（÷`scorable_frames_window / fps`） |
| 60–61 | `first_onset_s` 是**相对窗口起点**的秒数（`first_onset_frame / fps`） |

所以：

- `immobility_s` / `immobility_raw_s` **不是**从 `scorable_frames` 算出来的，它是 `window_frames/fps` 减掉 mobility。少了 `window_frames` 和 `fps`，读者根本不知道这个秒数是从多长的窗口里减出来的。⇒ **`("window_frames", "scorable_frames", "fps")`**（`scorable_frames` 留着，因为引擎的两种占比里有它）。
- `mobility_s` 是直接量出来的帧数 ÷ fps，`window_frames` **不是它的除数**，写成那样会让人以为它是个比例。⇒ **`("window_frames", "scorable_frames", "fps")`**（同一套：任何窗口内的秒数，都要能同时算出占窗口与占可评分）。
- `first_mobility_onset_s` 的除数确实只有 `fps`，**但它是相对窗口起点的**。FST 的窗口从 120 s 开始，光看这个数会被读成录像绝对时刻。⇒ **`("window_frames", "fps")`**，且列头必须写明「相对计分窗起点」。

**你交付报告里给的依据（「immobility 在 scorable_frames_window 范围内计算」）与 `trial_report.py:189-191` 直接矛盾**，请连依据一起改，并在 `DENOMINATORS` 上方的注释里写清行号。

## 二、守卫要求（每条都要变异吃劲，装饰的改到吃劲）

现有 9 条守卫我独立复验过两条确实吃劲（把 `not_scored_list = []` 变异 ⇒ `test_alarm_rows_must_not_disappear` + `test_missing_files_behavior` 红；把空值兜底成 `or "0"` ⇒ `test_blank_values_not_turned_into_zero` 红）。你报告里说「守卫 5 是变异脚本 bug、手动验证」—— **守卫本身没问题，是你的变异脚本有问题**，不用再改守卫 5。

新增（下面每条对应上面一个 F）：

1. **F1**：run.json 名册 4 个、CSV 只有 ch1/ch3、两个报警源**都为空** ⇒ 断言 4 行、ch2/ch4 是 alarm 且 `reason` 里点出「名册里有、产出里没有」。变异：把名册来源改回「CSV ∪ 报警源」必须红。
2. **F2**：无 CSV + run.json 名册 4 个 + 报警源全空 ⇒ 4 行 alarm。
3. **F3**：CSV 一行 `scored=False` + `gate_messages` 非空 ⇒ `kind="alarm"` 且 `reason` 含 gate_messages 原文；同时断言这一行的 16 个字段**还在**。
4. **F4**：`--trial-prefix` 与文件名不同，**跑真引擎**产出 CSV+run.json（照 `test_end_to_end_with_real_engine_output` 的路子），断言 scored 行与 alarm 行的 `trial_id` 前缀**相同**，且等于 `engine.trial_prefix(exp, i)`。再加一条 AST 守卫：`models/results.py` 里不许出现 `.stem`。
5. **F5**：**顶层必写键用循环**，清单从真引擎产出的 run.json 里 `json.load` 后取顶层键名生成（不许手写 —— 手写的清单在引擎加键时不会红）：逐个删掉一个键 ⇒ 必须抛 `ResultsError` 且错误里点出键名。嵌套的那几个（`chamber_validity[].status`、`not_scored[].chamber/reason`、`video.fps/name/frame_count_source`、`rules.theta_mob`）另写一条，逐个删、逐个断言。
6. **F6**：坏 `trial_id` ⇒ `ResultsError`，错误里含原始字符串。
7. **F7**：run.json 缺失 ⇒ 那行 `chamber is None`；再加一条：**任何夹具下，所有行的 `chamber` 要么是 `None`，要么 `≥ 1`**（负数或 0 即红）。不要写「源码里不许出现 -1」那种字面量守卫 —— F6 改完后 `split()[-1]` 之类的合法 `-1` 会让它误红，这种守卫最后一定会被人注释掉。
8. **F8**：拿真引擎产出的一行**回算**：`window_frames/fps − mobility_s ≈ immobility_s`（3 位小数容差）。这条同时钉住 `DENOMINATORS["immobility_s"]` 必须含 `window_frames` 与 `fps` —— 断言「回算用到的每一列都在 `DENOMINATORS[…]` 里」。**回算只许出现在测试里，模型层一个 `+`、一个 `/` 都不许有**（派工单 §5）。
