# 派工单共同约定 v1（每张派工单开头引用本文件，不要各自重写）

> 用法：新派工单写「**本单适用 `docs/派工单/_共同约定_v1.md` 全文**」，然后只写本单特有的东西。
> 本文件里的每一条都是本仓踩过的坑，改本文件要写清改哪条、为什么。

## 1. 数据形状纪律（写派工单的人最容易犯的错，比外派agent还容易）

| 规矩 | 反例 | 出处 |
|---|---|---|
| **未知不许长成数字的样子** | 总帧数未知传 `0`、时长未知填 `-1`、秒数未放行填 `0.0` | DP-099 复核（我自己派工单写的「总帧数未知时传 `0`」被打回）；CSV 里未放行的 `immobility_s` 一律留空 |
| 未知一律 `None` / 留空，类型写成 `X \| None` | `int` 里塞哨兵值 | 同上 |
| `None` 与 `""`、`None` 与 `0.0` 是**两件事**，序列化器不许用真假值抹平 | `x or ""`、`if x else None` | DP-099 复核第 4 条 |
| **一个数字只许有一个序列化器** | 同一个有效性既写 CSV 又写 run.json，而且取自两个不同对象 | 架构 §3.5；DP-054（198.9% 就是这么打出来的） |
| 键不许因为「值是空的」而省略 | `not_scored` 为空时省掉这个键 | 下游分不清「没有」和「没算」 |

**写字段清单时的自检**：清单里每一项，先问「这个数字 CSV 里有没有」。有 ⇒ 要么不写，
要么写清楚「只在 CSV 没有的那部分写」，不能既列进清单又在别处写一句「不许重复」——
自相矛盾的派工单，外派agent会照字段清单做，错算派工单的。

## 2. 判定参数与阈值

- run.json / 报告 / 导出里凡涉及「这批数字凭什么这么算」，**必须带上实际生效的判定参数**
  （至少 `θ_mob`，整份 `TstRulesParams` 更好），且**从 dataclass 现读，不许抄字面量**。
  抄了就是第二个真值。
- 分析入口（`analyze_video` / `analyze_frames` / `segment_series`）**不许新开参数覆盖口**。
  真要开，必须把实际生效的参数穿进 run.json，否则 run.json 会说谎——这条要有测试守。
- `θ_mob = 0.0175` 是 **FROZEN provisional**，只能由两人 ethogram 重标定，
  **绝不许用系统自己的输出重标定**。任何单子都不许改它。

## 3. 通用禁令（每单都适用）

1. 不许改验收门常量、阈值、`ASSAY_WINDOWS`、`CSV_FIELDS`（改一个字都算越界）。
2. 不许 `try/except: pass` 吞异常。静默兜底比报错危险（DP-052 / DP-054）。
   要退化就往 stderr 写清原因，而且 **stdout 一个字节都不许多写**。
3. 不许把进度/日志写 stdout；stdout 是人读报告，也是逐位比对的基线。
4. 不许做协作式取消（不看回调返回值、不加 `cancel_event`）。取消由外壳杀进程实现（架构 §3.4）。
5. 不许引入新的第三方依赖，除非本单明确列出。
6. 不许 `git add -A`；只 add 自己真正改的文件。
7. **不许把含 token 的 remote URL 写进任何文件、日志、commit message 或 PR 正文。**
8. 不许为了让本单「看起来过了」而放宽判据（例如把「逐位相同」改成「差不多」）。
9. 不许动不属于本单的目录（每单会写清自己的范围）。
10. 分支名写死在派工单里，不许自己改名。

## 4. 测试纪律

- 每条规矩都要有一个**踩上去会红**的测试，并且用变异测试证明它会红：
  改坏代码 → 只跑守它的那个测试 → `finally` 恢复原文 → 最后复跑全模块确认恢复干净。
  **能被跳过的守卫等于装饰**（DP-069 / DP-071 / DP-076）。
- 比较「两份结构里不许有重叠」时，按**语义**比（如按隔间号），不要按键名比：
  同一个数字在两处常常不同名（CSV `validity_status` vs run.json `chamber_validity[].status`）。
  也不要把递归展开的键名 `split(".")[0]` 收成最外层——那等于只比了最外层（DP-099 复核第 3 条）。
- 新测试模块必须登记进 `run_tests.py` 的 `TEST_MODULES`（有 meta-guard 会查）。
- 本仓不用 pytest，跑 `python3 run_tests.py`。

## 5. 交付报告要回答的（缺一条即退回）

1. 派工单每条验收判据，**逐条**写「怎么验的 + 实际输出」。
   验的不是派工单要求的那件事，等于没验（例：要求「与改动前 stdout 逐位相同」，
   报「`progress=None` 与 `progress=收集器` 输出相同」——是另一件事）。
2. 测试数目要与模块里实际的对得上（会被复核方重跑核对，对不上则报告整份不予引用）。
3. 哪些地方你觉得派工单写错了或自相矛盾 —— **这一条最值钱，照着错的做不算免责**。
4. 有没有改动派工单范围外的文件（有就说清为什么）。
5. 变异测试结果（每条守卫的红/绿）。
6. **CI 的 run id + 每个 job 的 conclusion，逐个贴出来。**
   本地跑绿、CI 红，这两件事同时成立时**只有 CI 算**——客户的机器不是你的沙箱。
   （DP-108 与 DP-110 连着两轮自报「全绿」，而各自 head 上的 `Desktop Self-Test` 是红的。）

## 6. 复核累积下来的通用铁律（DP-107 ~ DP-110，每一条都是真踩出来的）

| 铁律 | 反例 | 出处 |
|---|---|---|
| **不是把守卫改松，而是把代码改成守卫看不见的形状** —— 守卫误报就去改**守卫的作用域**，不许改被守的代码 | AST 黑名单禁 `2.0`，于是把引擎里一个和门槛无关的 `2.0 * bl` 改写成 `2 * bl`；顺手把 `0.02*bl*bl` 改成 `bl*bl/50`，**改变了引擎判定行为** | DP-109 A1 |
| **一条会误报的守卫，最后一定会被人绕过去；而绕它的那一下，往往比它防的那件事更危险** | 同上 | DP-109 A1 |
| **守卫要盯产品真正走的那条路，不许盯一份没人读的声明** | `EXPORT_SUFFIXES` 零产品读者，三条守卫全围着它；真正决定文件名的 `export_paths()` 自己又拼了一遍，把扩展名改成 `.xls` 零条测试变红 | DP-110 C9；同族：`ACQ_REFERENCE_KEYS` 零读者（DP-109 A5） |
| **一个常量「被读到」不等于它的「值是对的」** —— 门槛/阈值的**数值本身**必须与台账逐字对账 | 三个采集门常量各有一条「确实被读到」的守卫，把门槛放松 10× 却零条变红 | DP-109 A9 |
| **任何给用户看结论的地方，「不为空」不是要求，「说的是真话」才是要求** | 结论区兜底一句「全部指标通过」，而其中一门 `None`；导出弹窗标题「导出完成（有警告）」而三份产物全失败 | DP-109 A2 / DP-110 C12 |
| **黑名单判字符串常量必须用子串，不许用完全相等**；而且要想到 f-string 的字面段会被粘上别的字 | 禁 `".xlsx"` 用 `==`，于是 `f"{stem}_导出.xlsx"` 的字面段是 `"_导出.xlsx"`，全程失明。同族：门槛数字写进 `str` 常量躲开 float 黑名单 | DP-110 C10 / DP-109 A6 |
| **CI 里的 smoke 不许有可跳过的分支** —— `try/except → print WARNING → 步骤仍然绿`，等于这条 smoke 不存在 | ubuntu 上 PDF 渲染每一次都走 `except`、每一次都绿，PDF **从来没被渲出来过一次** | DP-110 C1 |
| **一份名册必须与它清点的东西双向对账** | MANIFEST 只验了 `声明.txt` 一条的 sha256，没有断言「MANIFEST 条目集 == zip 成员集」；模型键集只查「模型要的比引擎多」，不查反向 | DP-110 §5 / DP-109 A8 |
| **测试不许改写被 git 跟踪的产品数据文件** —— 复制到 tmpdir 改副本，路径做成可注入 | 守卫直接把 `data/validation_readings.json` 写成 `own_bias_s: "+999.99"` 再 `finally` 恢复；进程被杀就留在仓库里，而 CI 会绿 | DP-110 C11 |
| **测试名和 docstring 说了几处，就必须真有几处断言** | 「三份逐字相同」实际只有审计包逐字比、xlsx 只比第一行标题、PDF 一条都没有 | DP-110 C8 |
| **`tests/` 不是部署目录** —— 产品运行期读的任何数据必须在包内 | 引擎从 `tests/fixtures/p2_reference.json` 读参考值，冻结后永远缺失、静默变横杠 | DP-109 A4 |
| **中文编码归一化的边界分两处，不要互相「顺手清理」** | 我们自己的代码入口 ⇒ `main()` 的**第一句** `force_utf8()`（在任何 print 之前，stdout 和 stderr 都要）；workflow 里的 inline `python -c` 片段（没有我们的代码入口）⇒ **job 级 `env: PYTHONUTF8: "1"`** | DP-108 A1 / DP-110 C6 |
| **沙箱看不见的一整类 bug，只有 Windows CI 和 AST 守卫能看见** | `--help` 打中文在 Linux 上永远绿（stdout 默认 UTF-8），在 Windows 上 `cp1252` 直接炸成 rc 1，把 rc 0 / rc 2 的契约全冲掉 | DP-108 第 12 步 |
| **判断在模型层，摆放在页面层** | 页面里出现门槛比较、除法、round() | DP-107 / DP-109 |
| **一条断言自己 mock 的测试等于没测** | 三条字体测试喂给名字匹配器的正是它用来匹配的那份名单；真正决定客户能否导出的实测函数零测试 | DP-110 C3 |

> 沙箱缺 PySide6，所以 `desktop/app/pages/*.py` 在本地测试里**只被 AST 解析过，从来没有被构造过**。
> 页面上的摆放错误（把第 0 行的判定摆到第 2 行）本地一条测试都发现不了，只有 `desktop-selftest`
> 那条 CI 构造到了那一页才算测过。不要以为页面被测过了。
